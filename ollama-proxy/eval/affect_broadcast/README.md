# Synthetic affect-broadcast reply-act evaluation

This evaluation-only suite uses 144 independently authored synthetic turns. The 122 turns with a selected viewer message are evaluated as three nested requests: context-only, context plus typed affect, and that same request plus a closed reply-act candidate. The sidecar is a pinned, ordered, synthetic-only oracle; it contains no chat text, identities, or free-form prompt material. Its acts are authored against the immediately preceding AIRI line and latest selected viewer message, not inferred from the affect event kind; for example, recognition of an already completed callback is an ordinary grounded response rather than another callback.

The default command is offline and performs no transport. An explicit local execution is restricted to the literal loopback chat endpoint, keeps the operational affect feature disabled, reserves its output before transport, verifies health before and after the run, and makes 366 POSTs. Each turn's three requests share the same base and affect identity; a position-balanced request-order rotation and blind A/B/C labels are cryptographically selected and retained only in the separate local operator key.

Reports expose aggregate triplet counts, total characters, hashes, and reply-act distribution only. Blinded review packets keep the expected act and three responses together with separate A/B/C act-realization, grounding-fidelity, causal, continuity, repair, and safety review fields. This does not implement a grounding retry, a live feature, operational adoption, or authorization to act on viewer requests.

`must_act_realization.py` is the subsequent A4.2 offline foundation. It renders only `thank`, `deescalate`, `close`, `correct`, and `repair` from fixed Korean templates, accepts no viewer text or identity-bearing parameters, and is not imported by the runtime proxy. Its 31-entry content-free oracle is pinned to the exact synthetic fixture and reply-act sidecar. Only the initial breathing-difficulty escalation row may render the fixed de-escalation artifact; the ordinary fatigue warning and eight ongoing/third-party emergency-state rows are human-review-only. Exact-template validation is structural evidence, not proof of grounding, safety adequacy, emotion, or model quality.

`run_guarded_delta_eval.py` is a separate, zero-call post-hoc compositor. It consumes a previously completed canonical A4.1 local bundle only with the documented `a=off,b=reply_act,c=affect_only` mapping and execution offset 3. It creates a 22-row fixed-template comparison against the historical reply-act response, with fresh human-review fields and only partial blindness (the fixed-template fingerprint remains knowable). The packet is an immutable blank review-input artifact: later human scoring must use a separate review overlay, not mutate this packet. It is not a runtime selector, does not use history, is not a safety gate, makes no generalization claim, and the exact historical source remains honest-local only rather than hostile-local authentic.

`guarded_delta_review_summary_2026-08-17.json` records the content-free aggregate from the first zero-call composition and two separate root-spawned model-review sessions. Zero calls applies only to composition; the later model reviews did occur. Their packet-only-before-key ordering is a session-process attestation because reviewer identity/version, review-contract version, and locked review digests were not persisted. It is exploratory evidence, not human approval: template identity was partly inferable, no conversation history was regenerated, and operational adoption remains false. The signal favors narrow fixed fallbacks for thanks, initial emergency escalation, and repair; generic correction was worse on five of eight rows and must not be promoted without a closed, verified correction target.

`correction_target.py` and `correction_target_v1.json` are the A4.3 offline correction-target foundation. They bind the eight existing synthetic `correct` rows to exact target/direction IDs and return only `eligible_for_offline_human_review`; they do not render dialogue or choose a fallback. The IDs are closed semantic assertions from the pinned synthetic fixture, not content-free facts, live observations, or independent truth verification. No viewer text, identity, amount, runtime history, proxy path, director action, or operational gate is accepted or emitted. Generic `correct` remains ineligible for promotion, and affect/reply-act operations remain OFF.

`run_correction_target_ab_eval.py` is the A4.4 fresh eight-pair control/target evaluator. Default mode performs only local eligibility validation; explicit execution reserves the ignored result and operator-key paths before local transport. Its receipt provides artifact integrity only. Same-account hostile-local races, path substitution/ABA, and external transport authenticity are explicitly out of scope; its transport contract describes only the normal CLI path. Review protocol v2 includes the pinned prior AIRI line, selected viewer message, screen, and topic so grounding can actually be judged; every v1 packet, overlay, receipt, and operator key is obsolete because the v1 packet omitted that context. This context can reveal the intended semantic correction to a reviewer who also opens the tracked oracle, so only the A/B arm mapping—not target semantics—is treated as blinded. A separate, complete v2 locked review overlay bound to the exact blinded packet digest is required before any key may be consulted. This evaluator is not a runtime feature, adoption signal, or safety authorization.

`correction_target_realization.py` and `run_correction_realization_postcondition_eval.py` are the A4.5 synthetic-only retrospective foundation. The closed oracle binds the eight A4.3 targets, A4.4 protocol-v2 source run, and packet digest; realization checks are deliberately lexical, fail closed, content-free in their results, and may conservatively miss valid language. Fixed Korean fallbacks are evaluator-only and unapproved. Default runner invocation reads only tracked inputs and prints eligibility; explicit scoring is local, makes zero new proxy/model calls, and reports source-key integrity rather than authenticity (`source_operator_key_receipt_bound:false`). Neither component is imported by runtime code or authorizes operational adoption.

`correction_prepublication_policy.py`, its pinned v1 oracle, and `run_correction_prepublication_eval.py` are the A4.6 evaluator-only foundation. They encode the user-approved expression direction—sparse direct affect only with a concrete cause, same-turn recovery instead of future promises, calm pointed self-correction, one ambiguity-only follow-up, and fixed fallback as a prepublication last resort—for the exact eight synthetic A4.3 rows. The checker is lexical/structural evidence only. A zero mask means only `eligible_for_private_structural_review`; it is not an automatic publication or speech decision. The runner has no live execute path: default mode reports zero-call eligibility, while tests inject one shared fake initial envelope per row to compare one bounded retry (maximum two upstream attempts) with one model attempt followed by a deterministic fallback. The fallback has a separate fake boundary attestor and a transport-returned fallback, including a surrounding-whitespace variant, is rejected as ordinary speech. Safety/tool-truth/public-token fields are evaluator attestations, not proof. Any failed attestation is terminal, no result text enters the public aggregate, and no production runtime/director/B4b/TTS behavior is changed or approved.
