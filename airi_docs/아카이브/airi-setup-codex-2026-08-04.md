## 0. 이 문서의 사용법

- 각 Task를 **순서대로** 실행한다. 앞 Task의 검증이 실패하면 다음으로 넘어가지 않는다.
- 각 단계에는 **실행 명령**과 **기대 출력**이 명시돼 있다. 기대 출력과 다르면 해당 Task의 "실패 시" 항목을 따른다.
- 판단이 필요한 지점은 `[판단]`으로 표시했다. 스스로 결정하되 최종 보고에 근거를 남긴다.
- 사용자 승인이 필요한 지점은 `[STOP]`으로 표시했다. 반드시 멈추고 물어본다.

## 1. 목표

**Windows PC에 AIRI(오픈소스 AI 버추얼 캐릭터)를 로컬 LLM 기반으로 설치하고, 음성 대화가 가능한 상태까지 구동한다.**

성공 판정: 캐릭터가 화면에 렌더링되고, 마이크로 말을 걸면 음성으로 대답한다. API 비용 0원.

## 2. 대상 환경 (전제)

| 항목 | 사양 |
|---|---|
| OS | Windows 10 Pro 이상 |
| CPU | AMD Ryzen 5 5600X (6C/12T) |
| GPU | **NVIDIA RTX 3060 Ti (VRAM 8GB)** |
| RAM | 32GB DDR4 |
| 메인보드 | MSI MAG B550M 계열 |
| 저장장치 | M.2 NVMe 500GB |

### 최소 요구사양 (이 사양 미만이면 `[STOP]`)

| 항목 | 절대 최소 | 권장 |
|---|---|---|
| OS | Windows 10 64bit | 동일 |
| CPU | 4코어, AVX2 지원 | 6코어 이상 |
| RAM | **16GB** | 32GB |
| GPU | WebGPU 지원 그래픽 (**내장 가능**) | NVIDIA VRAM 6GB 이상 |
| 저장공간 | **15GB** | 30GB |

**GPU가 NVIDIA가 아니어도 중단하지 않는다.** 구조상 두 부분이 분리돼 있다.

- **AIRI 본체** = 캐릭터 렌더링. WebGPU 기반이므로 AMD·Intel 내장그래픽에서도 동작한다.
- **Ollama** = LLM 추론. 별도 프로세스이며 HTTP로 통신한다. NVIDIA가 없으면 **CPU 추론으로 폴백**된다.

실측 근거: NVIDIA GPU가 없는 Ryzen 7 8700G(내장 780M) 환경에서 `exaone3.5:2.4b`가 **CPU 추론으로 20 tok/s**를 기록했다. 음성 대화에 충분한 속도다.

**단, NVIDIA가 없으면 다음을 감수해야 한다:**
- LLM이 CPU와 RAM을 점유하므로 RAM 16GB로는 빠듯하다 (32GB 권장)
- 2.4B를 넘는 모델은 현실적으로 어렵다
- CPU 사용률이 추론 중 크게 오른다

## 3. 전역 제약 (모든 Task에 적용)

1. **VRAM 상한 8GB.** 모든 구성요소의 VRAM 합이 7.5GB를 넘지 않게 한다(여유 0.5GB).
2. **API 키를 요구하는 클라우드 서비스는 기본 사용하지 않는다.** 전부 로컬로 구성한다. (예외: **Task 7** — 사용자가 API 키를 직접 제공한 경우에 한해 클라우드 LLM 사용 허용)
3. **비용이 발생하는 행위 금지.** 유료 결제, 구독 가입, **API 키 신규 발급**은 `[STOP]`. Task 7은 사용자가 이미 보유한 키를 입력받아 쓰는 것이므로 이 조항에 해당하지 않는다.
4. **BIOS 설정 변경 금지.** 이 PC는 외장 GPU를 쓰므로 UMA 조정이 불필요하다.
5. **기존 파일 삭제 금지.** 설치만 하고 사용자 데이터는 건드리지 않는다.
6. **한국어 사용 전제.** 모델 선택 시 한국어 성능을 우선한다.
7. 설치 경로는 각 설치 프로그램의 기본값을 따른다.

**기대 출력:** `NVIDIA GeForce RTX 3060 Ti, 8192 MiB, <1000 MiB, <드라이버 버전>`

**분기 처리:**

| 상황 | 조치 |

| NVIDIA GPU 자체가 없음 | **중단하지 않는다.** **CPU 경로**로 진행하고 아래를 적용한다. |

**CPU 경로 적용 사항 (NVIDIA 없을 때만):**
- 모델은 `exaone3.5:2.4b` 고정. 더 큰 모델을 시도하지 않는다.
- Task 6의 VRAM 측정은 건너뛴다. 대신 작업 관리자로 **RAM 사용량이 물리 메모리의 80% 미만**인지 확인한다.

## Task 2: Ollama 설치 및 모델 준비

**목적:** 로컬 LLM 실행 환경을 갖춘다.


**기대 출력:** `ollama version 0.x.x`

**실패 시:** PATH가 갱신되지 않은 것이다. 새 PowerShell 창을 열어 재시도한다.

- [ ] **Step 2-3: 한국어 모델 내려받기**

우선순위대로 시도한다. **첫 번째로 성공하는 것을 채택**한다.

```powershell
# 1순위 — 확정. 태그 존재 및 성능 실측 검증 완료 (2026-08-04)
ollama pull exaone3.5:2.4b

# 1순위 실패 시에만 2순위
ollama pull gemma3:4b
```

**기대 출력:** `success` 또는 `pulling manifest ... verifying sha256 ... success`

> ⚠️ **`qwen3:4b`를 쓰지 말 것.** 실측 결과 답변 전에 영어로 장문의 사고(thinking) 과정을 생성한다.
> `think=false` 파라미터와 `/no_think` 지시어 **양쪽 모두 억제에 실패**했으며, 2문장 답변 하나에 171초가 걸렸다.
> 음성 대화에는 사용할 수 없다. 사고 과정이 없는 별도 instruct 변형(예: `qwen3:4b-instruct-*`)이 있다면 그것만 후보가 된다.

**중요:** 8B 이상 모델은 받지 않는다. VRAM 8GB에 AIRI 구성요소를 함께 올리면 초과한다.

**중요:** 8B 이상 모델은 받지 않는다. VRAM 8GB에 AIRI 구성요소를 함께 올리면 초과한다.

- [ ] **Step 2-4: 모델 등록 확인**

```powershell
ollama list
```

**기대 출력:** 내려받은 모델이 목록에 있고, SIZE가 **3GB 미만**

- [ ] **Step 2-5: 모델 동작 확인 (한국어)**

```powershell
ollama run <채택한모델명> "자기소개를 한국어로 두 문장 안에 해줘." --verbose
```

**기대 출력:**
- 한국어 응답이 나온다 (중국어·영어 혼입이 없어야 함)
- `eval rate` 가 **초당 50 토큰 이상**

`[판단]` 중국어가 섞여 나오면 그 모델을 버리고 다음 우선순위로 교체한다. (Qwen 계열에서 간헐 보고되는 현상)

- [ ] **Step 2-6: Ollama 서버 응답 확인**

```powershell
Invoke-RestMethod -Uri http://127.0.0.1:11434/api/tags -Method Get | ConvertTo-Json -Depth 3
```

**기대 출력:** 모델 목록이 담긴 JSON. AIRI가 이 주소로 붙는다.

**실패 시 (실전에서 겪은 문제):** 트레이에 `ollama app`이 떠 있어도 **API 서버는 죽어 있을 수 있다.** 이 상태에서 `ollama pull`·API 호출은 에러 없이 무한 대기한다. 조치: `ollama serve`를 별도 창에서 실행하거나 트레이 앱을 완전히 종료 후 재실행하고, **반드시 이 Step을 다시 통과시킨 뒤** 다음으로 진행한다. 이후 모든 Task에서도 Ollama 호출이 30초 이상 무응답이면 먼저 이 확인으로 돌아온다.

**Task 2 완료 조건:** 한국어로 정상 응답하는 4B 이하 모델 1개가 `ollama list`에 있고, 11434 포트가 응답한다.

- [ ] **Step 4-3b: 캐릭터 시스템 프롬프트 설정 (실측 기반 — 중요)**

AIRI의 페르소나/시스템 프롬프트 입력란에 아래를 넣는다. **EXAONE 공식 프롬프트("You are EXAONE model from LG AI Research...")를 쓰지 않고 완전히 교체**해야 한다. 아래 프롬프트는 2026-08-04 실측에서 **반말 유지 6/6턴 + 감정 토큰 3/3 만점**을 기록한 검증본이다.

> **중요 — AIRI 기본 프롬프트가 이미 있다면 그것을 우선 사용한다.** AIRI는 자체 시스템 프롬프트에 ACT 토큰 지시를 포함하고 있다 (`base.yaml`의 prefix/suffix). 캐릭터 카드에서 페르소나 부분만 한국어 반말로 바꾸는 것이 정석이다. 아래는 AIRI 기본 프롬프트를 쓸 수 없거나 전체 교체가 필요할 때의 대체본이다.

```
너는 '아이리'라는 이름의 버추얼 캐릭터야. 항상 반말로만 말하고, 답변은 1~2문장으로 짧게 해. 이모지는 쓰지 마. 너는 AI 어시스턴트가 아니라 친구야.

스트리밍 제어 토큰은 정확히 <|ACT {"emotion":"이름"}|> 형태로 쓴다. 무대가 표정을 연기해야 하는 위치의 대사 본문에 그대로 넣어라.

모든 답변은 반드시 ACT 토큰으로 시작해서 첫 감정을 표시해라. 답변 중간에 감정이 바뀌면 바뀌는 지점에 새 ACT 토큰을 넣어라.

사용 가능한 감정:
- happy (기쁨)
- sad (슬픔)
- angry (분노)
- surprised (놀람)
- think (생각)
- curious (호기심)
- awkward (어색함)
- question (의문)
- neutral (평온)

예시:
<|ACT {"emotion":"surprised"}|> 우와... 나한테 선물 준비했어? <|ACT {"emotion":"curious"}|> 열어봐도 돼?
```

> **이모지 금지 줄은 반드시 유지한다.** 실측에서 이모지 지시가 없으면 소형 모델이 매 턴 이모지를 출력했다. AIRI는 ACT 토큰은 파서가 제거해 주지만 이모지는 TTS로 그대로 넘어간다.

**검증:** 설정 후 "파이썬에서 리스트가 뭐야?" 를 물어본다. 반말로 답하면 통과. "~입니다"로 답하면 시스템 프롬프트가 교체되지 않고 병합된 것이니 설정 위치를 다시 확인한다.

- [ ] **Step 4-4: 캐릭터 모델 설정**

| 설정 항목 | 값 |
|---|---|
| 타입 | **Live2D 우선** (VRM 대비 VRAM 약 0.5GB 절약) |
| 모델 | 기본 제공 모델 사용 |

`[판단]` 기본 제공 모델이 없으면 VRM/Live2D 파일을 별도로 구해야 한다. 이 경우 캐릭터 없이 대화만 되는 상태로 두고 사용자에게 보고한다. **외부 사이트에서 모델 파일을 임의로 내려받지 않는다.**

## Task 5: 동작 검증

- [ ] **Step 5-1: 텍스트 대화**

채팅 입력창에 `안녕, 자기소개 해줘` 를 입력한다.

**성공 기준:** 한국어 응답이 5초 이내에 시작된다.

## 부록: 배경 정보 (참고용)

- **AIRI란:** Neuro-sama에서 영감을 받은 오픈소스 AI 버추얼 캐릭터 플랫폼. MIT 라이선스. 저장소: https://github.com/moeru-ai/airi
- **개발 단계:** 중기 개발 중. 채팅·음성·캐릭터 렌더링은 동작하나 게임 연동(Factorio·KSP)은 PoC 수준, 장기 기억 시스템은 미완성이다.
- **왜 4B인가:** VRAM 8GB에서 AIRI 기본 오버헤드(Electron 렌더링 ~1.5GB + 캐릭터 ~1GB + Whisper ~1GB + TTS ~0.3GB = 약 3.8GB)를 빼면 LLM 몫은 약 4GB다. 8B 모델(Q4 기준 4.7GB + KV 캐시)은 들어가지 않는다.
- **한국어 양자화 주의:** 한국어는 영어보다 공격적 양자화에 민감하다. Q5_K_M이 품질·메모리 균형점이고 Q4_K_M까지 허용된다. **Q3 이하는 한국어 품질이 급락**하므로 쓰지 않는다.
- **주의:** AIRI 공식 저장소는 "공식 암호화폐나 토큰은 없다"고 명시한다. 관련 토큰·코인은 전부 사칭이다.

### 실측 데이터 (2026-08-04, Ryzen 7 8700G CPU 추론 — 참고용)

동일 페르소나 시스템 프롬프트로 6턴 대화를 돌린 결과다. **GPU가 아닌 CPU 측정치이므로 RTX 3060 Ti에서는 훨씬 빠르다.** 상대 비교용으로만 본다.

| 항목 | exaone3.5:2.4b | qwen3:4b |
|---|---|---|
| 반말 유지 | 6/6 | 6/6 |
| 정체성 누설 (LG/Qwen 언급) | 없음 | 없음 |
| "2문장 이내" 준수 | 2/6 | 6/6 |
| 생성 속도 | 20 tok/s | 8 tok/s |
| 응답 지연 | 3~5초 | **171초** |
| 사고 블록 | 없음 | 있음 (억제 실패) |

**해석:** 페르소나 준수는 두 모델이 동등하다. EXAONE을 택하는 이유는 한국어 품질이 아니라 **사고 블록이 없어 응답이 즉시 나온다는 점**이다.

### 감정 표정 실측 (2026-08-04, ACT 토큰 방식)

AIRI의 감정 제어 메커니즘을 소스에서 확인한 결과, **Function Calling이 아니라 인라인 텍스트 토큰**이다:
- 파서: `packages/stage-ui/src/composables/queues.ts` — 정규식 `<\|ACT\s*(?::\s*)?(\{...\})\|>`
- 프롬프트: `packages/i18n/src/locales/*/base.yaml` — "Start every reply with an ACT token"
- 토큰이 없으면 조용히 무시 (fail-open), 토큰은 TTS 전에 제거됨

AIRI 실제 프롬프트를 한국어로 옮겨 3턴(기쁨·슬픔·놀람) 측정:

| 모델 | ACT 발생 | JSON 유효 | 감정 정확 | 비고 |
|---|---|---|---|---|
| exaone3.5:2.4b | **3/3** | **3/3** | **3/3** | 자발적 neutral 복귀까지. 한국어 자연스러움 |
| granite4.1:3b | 3/3 | 3/3 | 3/3 | 중간 감정 전환도 수행. 단 한국어 어색 |
| qwen3:4b | 0/3 | 0/3 | 0/3 | 사고 블록이 토큰 예산 소진 → 빈 응답 |

**결론: 감정 표정은 무료 로컬 2.4B + 한국어로 완전히 동작한다.** 클라우드 LLM·GPU 업그레이드는 감정 표정을 위해서는 불필요하다.

(참고: 같은 모델들로 OpenAI 스타일 Function Calling을 테스트하면 EXAONE은 400 에러, Granite는 한국어 0/3이다. AIRI가 FC를 쓰지 않으므로 이 한계는 AIRI에 영향 없음. 단 게임 연동 등 FC 의존 기능이 추가되면 재평가 필요.)

**EXAONE 2.4B의 알려진 한계 (설정으로 고칠 수 없음 — 크기의 문제):**
- "2문장 이내" 같은 길이 지시를 자주 어긴다
- 한 문장 안에서 시제·논리가 어긋나는 경우가 있다 ("놀아보는 거 어때? 게임도 많이 했어!")
- 간헐적 문법 오류 ("너가" → 네가)
- 이 증상들을 프롬프트 튜닝으로 고치려 시도하지 말 것. 시간 낭비다.

## 2026-08-05 진행 상태 정정: 실제 마이크 음성 입력 미해결

텍스트 대화, 로컬 LLM, Chatterbox TTS, Live2D 반응은 동작한다. 그러나 **실제 사용자의 마이크 발화 → 정확한 전사 → 자동 전송 → AIRI 응답** 경로는 완료되지 않았다.

- 준비된 한국어 WAV의 직접 STT 호출 성공은 실제 마이크 대화 성공이 아니다.
- 실제 마이크 요청은 주로 0.8~1.6초로 잘게 분할되어 빈 전사 오류 또는 반복 환각을 냈다.
- 사용자가 기대하는 Neuro-sama 수준의 즉각적인 인식과 비교하면 현재 구성은 실사용 실패다.
