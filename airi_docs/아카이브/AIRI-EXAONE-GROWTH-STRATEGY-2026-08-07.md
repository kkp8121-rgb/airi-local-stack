# AIRI EXAONE 기반 성장 전략 결정 및 메인 개발 세션 인수인계

- 결정일: 2026-08-07 (KST)
- 상태: 사용자 승인 방향
- 현재 단계: 개인 연구·개발, 당장 방송 또는 수익화 계획 없음
- 장기 목표: EXAONE을 현재 언어 코어로 사용하면서 AIRI를 Neuro-sama처럼 기억하고 반응하고 스스로 행동하는 AI 캐릭터로 성장시킨다.

## 1. 이번에 확정한 결정

1. 현재 기반 LLM은 `exaone-airi:2.4b`를 유지한다.
2. GPT-2로 교체하지 않는다. 현대적인 한국어 지시 수행, 문맥 처리, 캐릭터 대화 품질에서 현재 EXAONE이 더 적합하다.
3. 지금은 더 큰 모델로 교체하는 것보다 캐릭터 루프, 기억, 행동, 평가 데이터 계층을 먼저 만든다.
4. AIRI의 성장은 EXAONE 가중치 하나를 계속 덮어쓰는 방식이 아니라, 모델 위에 기억·성격·관계·행동·도구·학습 루프를 쌓는 방식으로 진행한다.
5. 당장은 비상업적 연구·개발을 계속한다. 공개 방송·수익화 전에 EXAONE 상업 라이선스를 취득하거나 상업 사용 가능한 기반 모델로 이전한다.
6. 기반 모델을 나중에 교체해도 AIRI의 정체성이 보존되도록 성격 명세, 기억 DB, 학습 데이터, 평가 세트와 도구 계약을 모델 밖의 독립 자산으로 관리한다.

## 2. “Neuro-sama급”의 의미

이 프로젝트에서 Neuro-sama급은 특정 비공개 모델을 그대로 복제하거나 동일한 인기도를 보장한다는 뜻이 아니다. 다음과 같은 사용자 체감을 목표로 한다.

- 한국어로 빠르고 자연스럽게 받아친다.
- 같은 말을 반복하면 횟수만 세는 것이 아니라 앞선 맥락과 의도를 고려해 반응한다.
- 사용자, 인물, 사건, 취향, 약속과 관계 변화를 세션을 넘어 기억한다.
- 성격과 말투가 장기간 안정적으로 유지된다.
- 감정과 관계 상태가 다음 반응에 영향을 준다.
- 화면, 채팅, 게임 이벤트를 관찰하고 먼저 말하거나 침묵할 수 있다.
- 도구와 게임별 실행 모듈을 사용하면서 실제로 하지 않은 행동을 했다고 주장하지 않는다.
- 좋은 반응과 나쁜 반응을 평가 데이터로 축적하고, 검증된 오프라인 학습을 통해 버전 단위로 개선된다.

즉 목표는 단일 LLM의 벤치마크 점수가 아니라 **지속적인 캐릭터 경험**이다.

## 3. 현재 판단과 근거

### 3.1 EXAONE 2.4B는 현재 단계에 충분하다

- 로컬 Ollama 모델 태그는 `exaone-airi:2.4b`다.
- 로컬 메타데이터 기준 전체 파라미터는 약 2.7B, 양자화는 Q4_K_M, 모델 파일 크기는 약 1.6GB다.
- 실제 AIRI 마이크 시험에서 사용자의 말이 끝난 뒤 첫 재생 추정치는 평균 약 1,764ms였고, 7회 중 6회가 2초 이내였다. 근거: [AIRI-FIX-HANDOFF-2026-08-07.md](./AIRI-FIX-HANDOFF-2026-08-07.md#10-실제-마이크-후속-검증-2026-08-07-밤)
- EXAONE 2.4B의 AIRI 감정 제어 토큰은 기존 시험에서 발생 3/3, JSON 유효 3/3, 감정 정확 3/3을 기록했다. 근거: [airi-setup-codex-2026-08-04.md](../airi-setup-codex-2026-08-04.md#감정-표정-실측-2026-08-04-act-토큰-방식)
- RTX 3060 Ti 8GB에서 STT, LLM, TTS를 함께 운용해야 하므로 빠른 소형 모델은 방송형 실시간 상호작용에 장점이 있다.

따라서 현재 체감 품질의 첫 번째 한계는 모델 크기보다 기억, 캐릭터 상태, 행동 판단과 데이터 루프다.

### 3.2 현재 구현 상태를 낡은 문서만 보고 단정하지 않는다

- 기존 수정 인수인계에는 장기 기억 설계가 완료됐으나 구현은 0%라고 기록돼 있다.
- 그러나 현재 미커밋 작업 트리에는 `ollama-proxy/airi_memory.py`, `memory_runtime.py`, `memory_prompts.py`와 관련 시험·벤치마크 파일이 존재한다.
- 이 파일들은 다른 작업의 진행 중 변경이다. 되돌리거나 덮어쓰지 않는다.
- 메인 개발 세션은 먼저 diff와 테스트를 검토하여 트랙 M의 실제 구현 단계가 M0, M1, M2 중 어디인지 재판정해야 한다.
- 시험과 런타임 통합을 확인하기 전에는 기억 계층을 완료로 선언하지 않는다.

### 3.3 이미 확보된 기반

- 실시간 한국어 STT → EXAONE → GPT-SoVITS → Live2D 파이프라인

- 감정 토큰과 표정 제어
- 도구 호출과 검색 사이드카
- 세션 내 반복 의도 감지와 EXAONE 대화 디렉터
- 지연 관측과 자동 시험
- 장기 기억용 SQLite·벡터·관계 1-hop 설계 문서

## 5. 핵심 설계 원칙

### 5.1 AIRI의 정체성은 기반 모델보다 위에 둔다

다음은 EXAONE 모델 파일과 분리해서 버전 관리한다.

- 캐릭터 헌법: 정체성, 가치관, 금지 행동, 말투 경계
- 상황별 행동 명세: 농담, 갈등, 실수 복구, 침묵, 되묻기
- 캐릭터와 사용자에 대한 구조화 기억
- 관계·관심도·감정 상태 전이 규칙
- 도구와 게임 에이전트의 입력·출력 계약
- 좋은 AIRI 대화 예제와 선호 데이터
- 성격, 기억, 안전성, 도구 정직성 평가 세트
- LoRA 어댑터와 학습 설정 및 기반 모델 버전

이 구조는 나중에 기반 모델을 교체할 때 AIRI의 성격과 기억이 함께 사라지는 것을 막는다.

### 5.2 기억과 학습을 분리한다

- 사용자의 이름, 취향, 약속, 사건은 먼저 DB/RAG 기억으로 처리한다.
- 반복적으로 나타나는 말투와 행동 성향만 검수 후 모델 학습 후보로 올린다.
- 최신 사실이나 개인별 기억을 모델 가중치에 굽지 않는다.
- 기억 검색이 실패해도 대화는 계속되는 fail-soft 원칙을 유지한다.

### 5.3 온라인 무검수 자기학습은 금지한다

생방송 채팅이나 모든 대화를 즉시 가중치에 학습시키지 않는다. 다음 위험이 있다.

- 악성 사용자의 데이터 오염
- 잘못된 사실과 유해 표현의 영구 학습
- AIRI 성격 붕괴와 말투 편향
- 기존 능력의 망각
- 개인정보의 모델 내 고착
- 실패 원인을 되돌리기 어려운 비가역적 변화

성장은 `수집 → 선별 → 수정 → 평가 → 오프라인 학습 → 회귀 시험 → 버전 배포` 순서로 진행한다.

### 5.4 게임 능력은 별도 모듈로 만든다

EXAONE에 픽셀부터 키 입력까지 전부 맡기지 않는다.

- 게임 상태 수집과 저수준 조작: 게임별 전용 모듈
- 현재 목표와 전략 선택: 계획기 또는 게임 에이전트
- 말할 내용, 감정, 시청자와의 상호작용: EXAONE 기반 AIRI

이 분리는 언어 모델을 바꾸지 않고도 게임 능력을 추가하고 시험할 수 있게 한다.

## 6. 단계별 성장 로드맵

### G0. 현재 작업 트리 재조정

목적: 진행 중인 기억 계층 변경을 보호하고 실제 상태를 확정한다.

작업:

1. `git status --short`, 전체 diff와 새 파일을 검토한다.
2. 기존 변경을 reset, revert, checkout하지 않는다.
3. 새 memory 파일의 단위 시험과 벤치마크를 실행한다.
4. 프록시 통합 여부, DB 경로, 원문 로그 정책, fail-soft 동작을 확인한다.
5. 트랙 M의 실제 완료 단계를 문서에 갱신한다.

완료 조건:

- 진행 중 변경의 소유와 범위가 파악된다.
- memory 단위 시험과 기존 proxy/STT/TTS 회귀 시험 결과가 기록된다.
- 구현 완료와 설계 예정 항목이 명확히 분리된다.

### G1. 캐릭터 루프

목적: 매 턴을 독립적인 질의응답이 아니라 이어지는 관계와 행동으로 만든다.

최소 상태:

- 현재 화제와 대화 목표
- 사용자 관심도와 AIRI 관심도
- 현재 감정과 감정 변화 원인
- 관계 단계와 친밀도 근거
- 마지막 질문·행동·도구 실행 결과
- 반복 의도와 앞선 응답의 충족 여부
- 침묵 시간과 최근 자발 발화 시각

원칙:

- 반복 횟수 같은 단일 숫자로 최종 대사를 강제하지 않는다.
- 안전과 실제 도구 실행 여부는 코드 경계로 지킨다.
- 캐릭터 행동은 최근 맥락과 모델 판단으로 결정한다.

### G2. 장기 기억

목적: 세션을 넘어 관계와 사건을 기억하되 잘못된 기억이 대화를 지배하지 않게 한다.

우선순위:

1. canon 성격과 세계관
2. 사용자·등장인물의 지속 특성
3. 약속과 중요한 사건
4. 관계와 관심사의 변화
5. 관련 순간과 최근 맥락

완료 조건:

- 앱과 서비스 재시작 후에도 검증된 기억을 회상한다.
- 다른 사용자·방·세션의 기억이 섞이지 않는다.
- 단순 반복, 일시적 자세와 감정, 잡음 발화를 영구 기억하지 않는다.
- 검색 실패나 임베딩 실패가 발화를 막지 않는다.
- 기억 검색 지연이 기존 트랙 M 목표 예산을 지킨다.

### G3. 평가 및 데이터 플라이휠

목적: “느낌이 좋아졌다”가 아니라 어떤 AIRI 버전이 실제로 나아졌는지 판정한다.

필요 기능:

- 응답 평가: 좋음, 나쁨, 수정 필요, 이유 태그
- 개발자가 작성한 더 좋은 AIRI 정답
- 두 응답 중 더 AIRI다운 것을 고르는 선호 쌍
- 오류 태그: 성격 이탈, 존댓말, 반복, 기억 오류, 도구 거짓말, 과도한 장문, 무반응
- 고정 평가 시나리오와 과거 실패 회귀 세트
- 모델·프롬프트·LoRA·메모리 스키마 버전 기록

현재 시스템은 음성 원문과 전사문을 기본 로그에 저장하지 않는다. 이 원칙을 유지한다. 학습 데이터 수집은 별도의 명시적 opt-in 내보내기와 검수 절차로만 추가한다.

### G4. EXAONE 성격 파인튜닝

시작 조건:

- 장기 기억과 캐릭터 루프의 경계가 안정화됐다.
- 충분한 고품질 수정 대화와 선호 데이터가 있다.
- 학습 전후를 판정할 고정 평가 세트가 있다.

방법:

1. Ollama의 Q4 GGUF를 직접 학습하지 않는다.
2. 원본 Hugging Face EXAONE 가중치로 LoRA/QLoRA를 학습한다.
3. 처음에는 성격과 대화 행동을 위한 SFT를 진행한다.
4. 충분한 선호 쌍이 쌓인 뒤 DPO 계열 학습을 검토한다.
5. 학습 결과를 병합 또는 어댑터 형태로 평가한 뒤 GGUF로 양자화하여 Ollama에 배포한다.
6. 기반 모델, 데이터셋, 어댑터, 양자화 설정을 모두 버전으로 고정한다.

RTX 3060 Ti 8GB에서는 2.4B QLoRA가 제한된 시퀀스 길이와 작은 배치로 가능할 여지가 있지만, 학습 중에는 Ollama, STT, TTS를 동시에 상주시킨다는 전제를 두지 않는다. 실제 학습 가능 여부는 작은 샘플로 메모리 게이트를 먼저 통과시킨다.

배포 게이트:

- 한국어 자연스러움과 AIRI 말투가 기준 버전 이상이다.
- 기억이 없는 질문에서 허위 기억을 만드는 비율이 증가하지 않는다.
- 감정 토큰과 도구 출력 형식이 깨지지 않는다.
- 기존 지식·지시 수행·안전 회귀 세트를 통과한다.
- 동일 프롬프트의 과도한 반복과 단답 고착이 증가하지 않는다.

### G5. 자발 행동과 방송 디렉터

목적: 질문을 기다리는 챗봇을 넘어 상황을 관찰하는 캐릭터로 만든다.

입력:

- 채팅 속도와 화제
- 침묵 시간
- 화면 변화와 게임 이벤트
- 최근 발화와 중복 가능성
- AIRI의 관심도, 감정, 관계와 현재 목표

출력:

- 말하기
- 기다리기
- 짧게 반응하기
- 질문하기
- 도구 사용하기
- 게임 행동 요청하기

스팸성 자발 발화를 막기 위해 발화 쿨다운, 중복 억제, 사용자 끼어들기 우선권과 행동 취소가 필요하다.

### G6. 화면·게임·채팅 에이전트

게임과 플랫폼별로 작은 기능부터 추가한다.

1. 읽기 전용 화면·게임 상태 관찰
2. 이벤트에 대한 말과 감정 반응
3. 제한된 안전 행동
4. 목표 단위 행동 계획
5. 실패 감지와 복구

게임 플레이 성능과 AIRI의 대화 성격을 별도의 시험으로 관리한다.

### G7. 기반 모델 및 라이선스 전환 게이트

다음 중 하나가 발생하면 기반 모델 재평가를 시작한다.

- 2.4B의 추론·도구 사용 한계가 평가 세트에서 반복적으로 확인된다.
- 더 큰 모델을 운용할 하드웨어 또는 별도 서버가 준비된다.
- 공개 방송이나 수익화 일정이 구체화된다.
- EXAONE 상업 라이선스를 취득할 수 있게 된다.

모델 교체 시 같은 캐릭터 명세, 기억 스냅샷, 데이터셋과 평가 세트를 새 모델에 적용해 A/B 평가한다. 단순 벤치마크 점수만으로 교체하지 않는다.

## 7. 모델 역할 분리

EXAONE 2.4B는 빠른 방송용 인격으로 유지한다.

```text
EXAONE 2.4B
  - 즉시 반응
  - 한국어 말투
  - 감정과 캐릭터 표현
  - 짧은 기억 기반 대화
  - 단순 도구 선택

선택적 큰 모델 또는 오프라인 평가기
  - 복잡한 계획
  - 긴 분석
  - 학습 데이터 검수 보조
  - 여러 도구가 필요한 어려운 작업
```

큰 모델은 당장 필수 구성요소가 아니다. 필요성이 평가로 입증될 때 추가한다.

### 7.1 EXAONE 모델 커스터마이징 결정

EXAONE 3.5의 공개 코드와 모델 가중치를 AIRI 연구용 파생 모델로 수정하는 트랙을 장기 계획에 포함한다. 다만 현재 우선순위는 구조 축소가 아니라 캐릭터 루프·장기 기억·평가 데이터 구축이다.

- 현재 `exaone-airi:2.4b` 원본 런타임은 기준 모델로 보존한다.
- AIRI 말투, 짧은 방송형 반응, 감정·행동 출력은 LoRA/QLoRA로 추가하는 방향을 우선한다.
- 개인 기억과 최신 사건은 가중치에 학습하지 않고 외부 기억 계층에 보존한다.
- EXAONE 내부의 지식은 언어·추론 능력과 얽혀 있으므로 “코딩·수학·영어 부분만 삭제”하는 방식은 사용하지 않는다.
- 레이어·MLP·Attention·어휘 프루닝은 평가 세트와 학습 데이터가 확보된 뒤 별도 연구 브랜치에서만 수행한다.
- 현재 Ollama GGUF는 직접 학습하지 않는다. Hugging Face 원본 가중치로 학습·구조 실험 후 GGUF로 변환하여 별도 모델로 배포한다.
- 수정 모델은 기준 모델과 A/B 평가하며, 속도·메모리 이득보다 한국어·성격·기억·도구 정직성 손실이 크면 중단한다.
- 연구용 파생 모델 이름은 라이선스 조건을 고려해 `EXAONE-AIRI-...` 형식으로 관리한다.

세부 기술 계획과 중단 기준은 [AIRI-EXAONE-MODEL-CUSTOMIZATION-PLAN-2026-08-07.md](./AIRI-EXAONE-MODEL-CUSTOMIZATION-PLAN-2026-08-07.md)에 분리한다.
