# AIRI 로컬 음성 입력 미해결 기록

> 기록일: 2026-08-05
>
> 상태: **미해결 / 실사용 실패**
> 범위: 이 PC에 구성한 AIRI 로컬 STT 경로. AIRI 자체 결함으로 확정한 기록이 아니다.

## 결론

텍스트 입력 → 로컬 LLM → Chatterbox TTS → Live2D 반응 경로는 동작한다. 그러나 사용자가 마이크로 말했을 때 자연스럽고 빠르게 인식하여 답하는 핵심 경로는 성공하지 못했다.

파일로 준비한 한국어 WAV를 STT API에 직접 전송하면 받아쓰기가 되지만, AIRI의 실제 마이크 입력에서는 발화가 지나치게 짧은 조각으로 전달된다. 그 결과 빈 전사로 `Voice input failed to transcribe speech.` 오류가 발생하거나, 실제 말과 무관한 반복 문장을 생성한다. 따라서 파일 입력 성공을 실제 음성 대화 성공으로 간주하면 안 된다.

사용자가 비교 기준으로 든 Neuro-sama는 발화를 거의 즉시 알아듣는다. 현재 로컬 구성은 이 반응성과 신뢰도에 미달한다.

## 현재 구성

- AIRI 0.11.3
- 입력 장치: `마이크(USB Audio Device) (1b3f:2008)`
- AIRI 음성 인식 제공자: OpenAI Compatible
- STT 엔드포인트: `http://127.0.0.1:8890/v1/`
- STT 모델 ID: `whisper-1`
- 실제 엔진: `faster-whisper base`, CPU `int8`
- 언어: 한국어(`ko`)
- 자동 전송: 켜짐, 지연 2초
- AIRI 모델 기반 VAD: 켜짐으로 표시되고 모델 로드 완료

## 재현 절차

1. 로컬 스택과 AIRI를 실행한다.
2. AIRI의 음성 입력을 켠다.
3. 사용자가 마이크에 한국어 문장을 말한다.
4. 다음 중 하나가 발생한다.
   - `Voice input failed to transcribe speech.` 오류
   - 입력한 말과 무관한 짧은 문장
   - 같은 낱말이나 문장의 장문 반복
   - 응답까지 이어지지 않음

## 관찰 근거

STT 서버 접근 로그상 AIRI는 `/v1/audio/transcriptions`에 요청을 보내며 HTTP 200을 받았다. 따라서 단순한 서버 미실행이나 URL 연결 실패는 아니다.

실제 마이크 경로에서 관찰한 요청 예:

| 오디오 길이 | RMS | Peak | 결과 |
|---:|---:|---:|---|
| 1.009초 | 0.00517 | 0.0680 | 빈 전사 |
| 0.819초 | 0.01871 | 0.2133 | 빈 전사 |
| 0.789초 | 0.00323 | 0.0248 | 5글자 오인식 |
| 1.159초 | 0.00889 | 0.0932 | 334글자 반복 환각 |

반면 준비된 한국어 WAV를 같은 STT 서버에 직접 보낸 검증에서는 약 6.04초 오디오를 정상 전사했다. 이는 모델 파일과 HTTP 호환 계층이 최소한 파일 입력에서는 동작하지만, 실시간 마이크 캡처·발화 분할·무음 판정 경로가 실사용에 적합하지 않다는 뜻이다.

## 시도했지만 해결되지 않은 조치

- Windows 마이크 권한 및 기본 입력 장치 확인
- OpenAI Compatible STT URL·모델·API 키 설정 확인
- faster-whisper의 무음/로그 확률 조건 완화
- `condition_on_previous_text=False` 적용
- 서버에 오디오 길이·RMS·Peak·전사 길이 진단 로그 추가
- AIRI 자동 전송 및 모델 기반 VAD 상태 확인
- 동일 STT 서버에 한국어 WAV 직접 전송 테스트

조건을 과도하게 완화하면 빈 전사는 줄 수 있으나 짧은 잡음 구간에서 반복 환각이 크게 증가했다. 따라서 이 상태를 해결로 판정하지 않는다.

## 다음 작업의 기준

다음 담당자는 TTS나 LLM을 다시 튜닝하기 전에 실제 마이크 경로부터 고쳐야 한다.

1. AIRI가 STT에 보내는 녹음 파일을 안전하게 보존하여 실제 발화 전체가 들어 있는지 확인한다.
2. 0.8~1.6초 조각이 반복 생성되는 원인을 AIRI 캡처/VAD와 로컬 STT 중 어느 쪽인지 분리한다.
3. 필요하면 배치형 `faster-whisper base` 대신 한국어 저지연 스트리밍 STT 또는 더 안정적인 발화 종료 감지를 사용한다.
4. 스피커 출력이 마이크로 재입력되는 피드백을 차단한다.
5. 아래 성공 조건을 실제 사용자 발화로 통과하기 전에는 완료로 표시하지 않는다.

## 완료 조건

- 사용자가 보통 크기로 한국어 한 문장을 말한다.
- 발화 종료 후 체감상 즉시 정확한 문장이 채팅에 한 번만 입력된다.
- AIRI가 해당 문장에 답하고 TTS로 한 번만 재생한다.
- 빈 전사 오류, 반복 환각, 자기 음성 재입력 루프가 없다.
- 위 검증을 연속 5회 통과한다.
