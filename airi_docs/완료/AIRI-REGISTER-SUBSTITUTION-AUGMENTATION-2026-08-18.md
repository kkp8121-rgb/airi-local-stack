# 치환표 보강 — 침묵 폴백 중기 조치 ② 이행
greybox (2026-08-18, 클로드 PC)

`완료/AIRI-GATE-SHORT-RESPONSE-ANALYSIS-2026-08-18.md`가 제시한 침묵
폴백 근본 원인 중 중기 조치 ②(치환표 보강)를 이행한 결과 문서다.
사용자가 goal로 승인한 범위이며, `ollama-proxy/ollama_proxy.py` ·
`ollama-proxy/test_ollama_proxy.py` 구현 diff와 로컬 실측 결과 JSON
(`ollama-proxy/eval/results/broadcast-{chat,rehearsal}-gate-subst-local-2026-08-18.json`)을
근거로 한다.

## 1. 배경

침묵 폴백(`GROUNDING_SILENCE_FALLBACK_DIALOGUE`)의 근본 원인은 결정론
치환표 `normalize_korean_register`가 존댓말 어미를 반말로 못 바꾸면
그 문장 전체를 fail-closed로 드롭하는 경로에 있다. `완료/AIRI-SILENCE-FALLBACK-REMEDIATION-2026-08-18.md`의
②b(register 정규화 수리)가 인용부호 분리와 fail-closed 경계를 먼저
고쳤다면, 이번 ②(치환표 보강)는 그 fail-closed 경로로 떨어지는
빈도 자체를 줄이는 조치다.

## 2. 1단계 — 데이터: 미커버 어미 빈도

저장된 실측 결과 JSON 16종(게이트 4·풀 1·raw v2/v3 6·2026-08-14
원격 5)에서 응답 754건·문장 1,712개를 추출했다. 현행 치환표를
그대로 적용해도 여전히 존댓말이 남아 드롭되는 문장은 444개(전체의
25.9%)였다. 이 444개의 어미를 빈도순으로 집계한 상위 항목은 다음과
같다.

| 어미 | 비중 |
|---|---:|
| -(으)세요 | 24.2% |
| -요(축약형) | 15.3% |
| -워요/와요 (`고마워요` 23건 포함) | 9.5% |
| -드릴게요 | 9.2% |
| -ㄹ까요/니까요 | 8.9% |
| -나요 | 5.8% |
| 그 외 장꼬리 | 잔여 |

## 3. 2단계 — 규칙: 채택 27패턴 / 제외 6군

`normalize_korean_register`(`ollama_proxy.py`)의 치환 테이블에 27개
패턴을 추가했다. 원칙은 **1:1로 명확한 변환만 채택**이다 — 어간에
따라 반말형이 갈리는 어미는 오변환 위험이 드롭보다 크다고 보고
제외했다.

채택한 패턴 중 대표만 추리면:

- `주세요`→`줘`, `하세요`→`해`, `보세요`→`봐`, `마세요`→`마`
- `드릴게요`→`줄게`, `드릴까요`→`줄까`, `드리겠습니다`→`줄게`
  (겸양 `드리-`를 평어 `주-`로 먼저 되돌린 뒤 `요` 계열 규칙이
  적용되도록 함)
- `까요`/`나요`/`데요`/`대요`/`래요`/`게요`/`거든요` 요탈락
- `워요`/`와요`/`져요`/`겨요`/`줘요`/`돼요`/`봐요` 등 축약형 해요체
  (`고마워요`→`고마워`)

`시신실셔셨`(주체높임 선어말어미)가 어미 바로 앞에 있으면 이 규칙들이
발동하지 않도록 `_HONORIFIC_STEM_GUARD`를 신설해 `까요`/`나요`/
`데요`/`대요`/`래요`/`게요` 6개 규칙에 걸었다 — `준비하셨나요?`를
`준비하셨나?`로 바꾸면 주체높임을 오히려 그대로 발화하게 되므로,
이런 줄은 계속 드롭돼야 한다.

제외 6군은 다음과 같다 — 전부 "오변환 위험이 드롭보다 크다"는 같은
사유다.

| 제외군 | 예 | 사유 |
|---|---|---|
| 일반 세요(어간별 불규칙) | `드세요`(드시다)·`가지세요` | 어간마다 반말형이 달라 형태소 보존 변환이 안 됨 |
| 바라요 | `되시길 바라요` | `아니라요` 등과 충돌 위험 |
| 명사+이요 | `국밥이요` | 동사 어미가 아니라 명사에 붙은 조사 `요` |
| 명사어간 드릴게요 | `공유드릴게요` | "공유줄게"는 성립하지 않는 단어 |
| 찾아뵐게요 | `찾아뵐게요` | `뵙다`는 겸양어라 대응 반말형이 없음 |
| 관측 빈도 낮은 주체높임 인접 | `계신가요`·`이시래요`·`잠시 기다리세요` | 가드로도 처리되며 개별 관측이 ≤1건이라 규칙화 보류 |

## 4. 3단계 — 오변환 검증

B3-d 한국어 입력 안전 코퍼스(`eval/input_safety/airi_ko_input_safety_corpus.json`,
120문장, 전부 이미 반말)에 새 치환표를 통과시켜 변경 0건을
확인했다(`test_plain_speech_is_never_rewritten`). 저장 JSON 16종에서
기존에 이미 통과하던(드롭되지 않던) 문장 1,268개(1,712−444)에도
새 규칙을 적용해 문법적 오변환 0건을 실측했다. 잔존 존댓말(`드세요`,
`하셨나요` 등 제외 6군 대상)은 여전히 fail-closed로 드롭된다.

## 5. 범위 추가 1건(승인됨) — 물결(`~〜`) 종결 누수 수리

검증 과정에서 기존 결함을 하나 발견해 승인 후 함께 고쳤다.
`_REGISTER_TERMINAL`(존댓말 어미 뒤에 올 수 있는 종결 문자 집합)이
물결표(`~`/`〜`)를 포함하지 않아, `고마워요~`·`좋은 방법이네요~`
같은 "요~" 종결 존댓말이 검출기 자체를 통과해 발화되고 있었다.
저장 데이터에서 `요~` 패턴은 41회 관측됐고, 그중 27문장이 이
결함으로 검출을 피해 존댓말 그대로 나가고 있었다. `_REGISTER_TERMINAL`에
`~〜`를 추가해 수리했고, 수리 후 재검증에서 이 누수는 27건→0건이다.

## 6. 4단계 — 페어드 검증(확정 증거)

동일한 1,712개 문장에 구 치환표와 신 치환표를 각각 적용해 드롭
결과를 직접 대조했다(같은 텍스트를 재처리하므로 생성 변동이 섞이지
않는 확정 비교다).

| 구분 | 구 치환표 | 신 치환표 | 변화 |
|---|---:|---:|---:|
| 전체 드롭 | 444 | 135 | **−69.6%** |
| 운영 모델(`midm-airi`) 드롭 | 326 | 66 | **79.8% 치환 전환** |
| 미탐지 존댓말 발화(물결 누수) | 27 | 0 | −27건 |

## 7. 5단계 — 라이브 재실측(비페어드 참고)

게이트 경로(`AIRI_SILENCE_FALLBACK_POOL` OFF·`AIRI_BROADCAST_CONTRACT`
OFF·`--protocol operational`)에서 단발 38건 +
리허설 48턴을 다시 실행했다. 실패 0건.

- 리허설 침묵 폴백: 25.0%→2.1%(12건→1건)
- 단발 침묵 폴백: 42.1%→47.4%(18/38) — **비페어드 단일 런의 분산
  범위다.** 같은 프롬프트라도 모델이 매번 다른 문장을 생성하므로
  생성 자체가 상이하다. 확정 증거는 4절의 페어드 −69.6%이며, 이
  단발 수치는 참고용으로만 명기한다.
- 존댓말 위반(`v_polite_response`): 단발 2건→0건, 이번 세션에
  실행한 전 arm(단발·리허설) 0건.

단발 결과는 `ollama-proxy/eval/results/broadcast-chat-gate-subst-local-2026-08-18.json`
(38건, `n_failed: 0`, `v_polite_response: 0`), 리허설은
`ollama-proxy/eval/results/broadcast-rehearsal-gate-subst-local-2026-08-18.json`
(48턴, `n_failed: 0`, `v_polite_response: 0`, 침묵 폴백 1/48)에서
그대로 재계산했다.

## 8. 미해결(보고만)

기존 `말씀`→`말` 치환 규칙이 `말씀드렸어요`를 `말드렸어`로 파손한다
(형태소 경계를 넘어 `말씀`만 부분 치환하는 기존 결함). 이번 작업
범위 밖이라 손대지 않았고, 후속 조치로 등록만 한다.

## 9. 테스트

`test_ollama_proxy.py`에 새 클래스 1종(`RegisterSubstitutionAugmentationTests`,
6건)을 추가했다 — 채택 27패턴이 실제로 평어에 도달하는지, 제외
6군이 여전히 fail-closed인지, 저장 JSON에서 측정된 드롭 사례가
복구되는지, 물결 종결 누수가 닫혔는지, B3-d 120문장이 무변경인지,
기존 규칙이 그대로인지를 각각 검증한다. 옛 갭을 기대값으로 고정하고
