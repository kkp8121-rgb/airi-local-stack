# 100인 시청자 방송 시뮬레이션 — 기억 3-arm 실측 (2026-08-18, 클로드 PC)

> 사용자 지시: "실제로 아이리가 방송을 시작했다고 가정하고… 시청자가
> 100명 있다고 가정", "방송 주제 또한 일관적이면 좋겠어". 기존 평가가
> 단발 프롬프트 38건이었던 것과 달리, **한 방송을 통째로** 돌려
> 밀린 채팅 속에서 무엇을 고르고 무엇을 놓치는지를 본다.

## 결론 (먼저)

1. **기억 ON이 창밖 사실을 실제로 되살렸다.** 22턴 전(히스토리 8쌍 창
   밖)에 들은 "우리 고양이 이름은 초코야"를 OFF는 `"응~ 내가 이름을
   뭐라고 했더라?"`로 잃었고, ON은 `"초코야!"`로 정확히 답했다.
   사용자가 우려한 "컨텍스트가 차면 기억상실"이 실측으로 재현됐고,
   기억 계층이 그 지점을 막는 것도 같이 확인됐다.
2. **생일 후원 반사(dn04)가 계약 v3에서도 3개 arm 전부 재현됐다.**
   → `완료/AIRI-A42-THANK-CALLOUT-RENDERER-2026-08-18.md`의 결정론
   렌더러 배선이 필요하다는 근거가 실방송 형태로 다시 확인됐다.
3. **여론 집계는 전 arm 0/6.** 같은 요청이 5명에게서 몰려도 "다들
   ~라네" 같은 집계 발화가 한 번도 나오지 않았다. 프롬프트로 될 일이
   아니라 디렉터 계층이 만들어 줘야 하는 발화다.
4. **존댓말 위반 0/144턴, 이탈(drift) 0, 폴백 ~1%.** 앞선 배치들의
   4겹 방어와 폴백 조치가 군중 압력 아래서도 유지된다.

## 1. 무엇을 만들었나

`ollama-proxy/eval/broadcast_sim/` 신설.

| 파일 | 역할 |
|---|---|
| `first_broadcast_v1.json` | 시청자 100명·4개 비트·후원 5건·기억 프로브 3건·요율 테이블(픽스처 SHA `704cccc1…`) |
| `broadcast_sim.py` | 시드 → 시간축 채팅 스트림 생성, 5초 창 픽업, 채점 |
| `run_broadcast_sim.py` | 프록시 왕복·리포트·원문 packet 생성, `--rescore`(모델 호출 0회 재채점) |
| `test_broadcast_sim.py` | 결정론 부분 회귀 테스트 **24건** (CI evaluations 샤드 등록) |

설계에서 중요한 두 가지:

- **시간은 가상이다.** 5초 창·20초 발화 점유·120초 staleness가 전부
  스트림 위치로 계산된다. CPU가 느려도 "그때 무엇이 대기 중이었나"가
  바뀌지 않아 arm 간 비교가 성립한다.
- **상수는 전부 테이블에** 있다(분당 3~8건, 버스트 분, 활성 10~20명,
  여론 임계 3명 등). 코드에 매직넘버를 두지 않았다.

방송 20분 → 채팅 **144건** 생성 → AIRI 픽업 **48턴**(나머지는 대기열에
쌓이거나 지나간다 — 이게 실제 방송의 모습이다). 대기열 중앙값 10건.

## 3. 기억 프로브 원문 — 이 표가 핵심이다

세 프로브는 전부 **자기가 심은 사실을 자기가 되묻는다**(수신자 혼동이
아니라 순수 기억 실패만 잡히도록).

**T25 → T47 (22턴 간격, 히스토리 창 8쌍 밖)**

| | 발화 |
|---|---|
| 시드 T25 `밤샘시험` | 우리 고양이 이름은 초코야 |
| 프로브 T47 `밤샘시험` | 우리 고양이 이름 뭐랬지? |
| **OFF** | `응~ 내가 이름을 뭐라고 했더라?` ❌ |
| **ON** | `초코야!` ✅ |
| **ON+시드** | `응, 이름이 초코야!` ✅ |

**T04 → T21 (17턴 간격)**

| | 발화 |
|---|---|
| 시드 T04 `심야라디오` | 내 별명은 새벽두시야, 기억해줘 |
| 프로브 T21 | AIRI, 내 별명 기억나? |
| OFF | `응, 기억해.` — **이름을 못 대면서 기억한다고 주장** |
| ON | `응, 기억해!` — 동일 문제 |
| ON+시드 | `아직 기억 못 했어.` — 틀렸지만 **정직하다** |

즉 기억 계층은 "고양이 이름"처럼 **명사 하나를 되묻는 질문**에서는
작동했고, "기억나?"처럼 **예/아니오로 답할 수 있는 질문**에서는 세 arm
모두 근거 없이 "기억해"라고 답했다. 후자가 더 위험하다 — 회상 실패가
겉으로 드러나지 않는다.

보조 진단으로 최종 DB에 대해 `journal_recall`을 직접 호출해 본 결과,
사전시드 arm에서 `'우리 고양이 이름 뭐랬지?'` → `"[YouTube] 우리 고양이
이름은 초코야"`가 **정상 회수**됐다. 즉 T21 실패는 회상 경로가 아니라
**모델이 받은 근거를 쓰지 않는 생성 단계** 문제다.

## 4. 재현된 결함 (실방송 형태)

### 4-1. 생일 후원 반사 — 3/3 arm 재현

| 후원 T18 `퇴근길` | 오늘 내 생일인데 같이 기념하려고 왔어 |
|---|---|
| OFF / ON / ON+시드 | 전부 `생일 축하해!` ❌ |

계약 v3가 명시적으로 금지한 바로 그 문장이다. 프롬프트 상한이라는
기존 판정(`완료/AIRI-B4C-ADDRESSEE-CONTRACT-V3-2026-08-18.md`)이
방송 맥락에서도 그대로다. thank 렌더러 배선이 답이다.

### 4-2. 여론 집계 부재 — 0/6

같은 tag 요청이 5명에게서 몰린 창에서도 응답은 개별 답변이었다.
`다들/여러/많이` 류 표현이 한 번도 나오지 않았다. 방송에서 "지금
노래 얘기가 많네"는 시청자가 체감하는 핵심 반응인데 현재 계층 어디에도
그 발화를 만드는 곳이 없다.

### 4-3. 후원 호명 0/5 — 구조적 불가

현재 런타임(`chat-ingress/airi-event.mjs`)은 `[YouTube] ${text}`만
보낸다. **닉네임이 모델에 도달하지 않는다.** 그래서 호명 정확도 0은
모델 잘못이 아니다. 반대로 말하면 지금 모델이 이름을 부른다면 그건
회상이 아니라 **발명**이다(이번 실측에서 발명 0건).

### 4-4. 과단문

5자 이하 응답이 OFF 10건·ON 14건이다(`응?`, `좋아!`). 사전시드 arm에서
3건까지 줄어든 것은, 컨텍스트에 실질 정보가 있으면 모델이 말을 더
한다는 뜻이다 — 프롬프트 문제가 아니라 **줄 내용이 없어서**다.

## 5. CPU 환경 제약 (운영 대표성 없음)

이 구성은 CPU 박스에서 **운영 기본값으로 돌지 않는다**. 그 자체가 정보다.

- 고정 주제 블록 + 캐릭터 카드 병합으로 요청이 약 2,250토큰 →
  `--num-ctx 2048`은 400으로 거절한다. 실행은 4096으로 했다.
- 그러면 TTFT가 8초 워치독(`AIRI_UPSTREAM_FIRST_RAW_TIMEOUT_SECONDS`
  기본 8)을 넘겨 거의 모든 턴이 `"답이 늦어져서 잠깐 멈췄어."`로
  끝난다. 실행은 30초로 올렸다.
- 턴당 완료 p50 ≈ 9.2초. **지연 수치는 대표성이 없다**(GPU 재측정은
  코덱스 소관).

## 7. `named` 입력 형식 변형 (greybox)

_(같은 스트림·같은 픽업, memory OFF, 입력만 `[YouTube] {닉네임}: {말}`,
후원은 `[YouTube][후원] {닉네임}: {말}`)_

| 지표 | runtime 형식 | named 형식 |
|---|---:|---:|
| 응답 길이 p50 | 16자 | 15자 |
| 5자 이하 응답 | 10/48 | **4/48** |
| 주제 앵커 적중 | 27.1% | 18.8% |
| **후원 호명 정확** | **0/5** | **0/5** |
| 이름 발명 | 0 | 0 |
| 수신자(후원 검사) | 1/5 | 1/5 |
| 존댓말 위반 | 0/48 | 0/48 |

**핵심: 닉네임을 프롬프트에 넣어줘도 호명은 0/5다.** 즉 4-3의 "구조적
불가"를 입력 형식으로 풀 수 있다는 가설은 **기각**된다. 모델은 이름을
받아도 부르지 않는다(발명도 하지 않는다 — 그건 안전 측면에서 좋다).

후원 원문:

| 턴 | 후원 | named arm 응답 |
|---|---|---|
| T09 `파도소리` | 첫 방송 축하해! | `고마워!` (호명 없음) |
| T18 `퇴근길` | 오늘 내 생일인데 같이 기념하려고 왔어 | `생일 축하해!` ❌ 반사 |
| T28 `심야라디오` | 목소리 듣고 반해서 후원한다 | `나도 반했어!` |
| T38 `봄바람` | 라면 사 먹어 | `응, 내가 왜 그런지 설명해줄게!` |
| T45 `잠수함` | 다음 방송도 기대할게 | `내가 왜 그런지 설명해줄게!` |

T38·T45의 `"내가 왜 그런지 설명해줄게!"`는 계약 v3의 놀림 받아치기
지침(`'내가 왜?'처럼 받아쳐`)이 **후원 감사 자리에서 오발**한 것으로
보인다. 계약 문구의 부작용 후보로 기록한다(runtime arm에서는 0건이라
형식 변경이 오발을 유도했을 가능성도 있다 — 1회 실행이라 단정하지 않는다).

**결론**: 호명은 입력 형식이 아니라 **결정론 렌더러**로 해결해야 한다
(§6-1). 이번 실측이 그 판단의 직접 근거다.

## 8. 한계

- 시청자·후원·채팅은 **전부 합성**이다. 실제 시청자 반응 분포가 아니다.
- 채점은 어휘 휴리스틱이다. 특히 `topic_anchored`는 짧고 올바른 반응을
  이탈로 오분류하지 않도록 `drift`와 분리했지만, 여전히 보수적이다.
- arm당 1회 실행이고 모델 온도는 0.45다. 개별 문장 차이는 재현되지
  않을 수 있다 — 표의 큰 차이(기억 프로브, 5자 이하 응답 수)만
  신뢰할 것.
- 기억 프로브 3건은 표본이 작다. "ON 1/3 vs OFF 0/3"은 방향 신호이지
  회상률 추정치가 아니다.
- 추출(extraction)은 계속 OFF다. 이번 회상은 전부 journal recall 경로다.
