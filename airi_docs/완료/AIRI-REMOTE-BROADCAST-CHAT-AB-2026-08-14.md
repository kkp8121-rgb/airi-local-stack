# 원격 방송 채팅 A/B — Mi:dm vs Motif (2026-08-14, 검토 PC)

사용자 지시: "dev PC에 모델을 실행했는데 어떤 LLM을 선택할지 결정하기
위해, 확보한 방송용 채팅 데이터로 테스트해봐. 응답 시간도 TTS와 별개로
체크 — 원격 왕복이라 실제 응답 시간과 비슷하게 나올 것."

## 구성

- 경로: 검토 PC → Tailscale HTTPS → dev PC 서버
  (`https://home.tail3687f8.ts.net:11439/v1`, Bearer 인증, 비스트리밍).
  **이 지연은 "방송 중 원격 LLM" 시나리오의 체감치를 그대로 근사한다.**
- 모델: `midm-airi:2.0-mini`(Q4_K_M, llama.cpp 계열) vs
  `motif-airi:2.6b-v1.1-lc-nf4`(NF4, transformers 계열) — 방송용 8GB 운용
  경로 정밀도이며 네이티브 BF16 비교와 정밀도가 다름(dev PC 고지).
- 입력: **실제 방송 트랜스크립트에서 역추출한 시청자 채팅 38건**
  (실측 32 / 합성 6, 8개 카테고리 — B4 픽업 우선순위 정합.
  `ollama-proxy/eval/broadcast_chat/broadcast-chat-fixtures.json`).
  개인정보·방송인 고유 밈 정제 완료.
- 프롬프트: 운영 `AIRI_SYSTEM_PROMPT` 원문(SHA-256 레포 일치 검증) +
  방송 프레임(코덱스 리허설 문장 재사용) + B3-c 실제 형식 `[YouTube] {채팅}`.
- 측정: **TTS 제외** 순수 LLM 완료 시간. 서버가 스트리밍 미지원이라 TTFT
  측정 불가 — 완료 기준 3단 분해(실측 / max_tokens=1 바닥선 / 추정 순수
  추론). warmup 집계 분리, keep-alive 재사용.
- 러너: `ollama-proxy/eval/broadcast_chat/run_broadcast_chat_ab.py`
  (mock 검증 완료 — 401·스트리밍 거부·warmup 분리·채점기 단위 19케이스).
  원 응답 전문:
  `ollama-proxy/eval/results/broadcast-chat-ab-remote-2026-08-14.json`.

## 결과 (76/76 성공, 실패 0)

### 지연 (완료 기준, ms)

| 모델 | 완료 p50 | 완료 p95 | 바닥선 | 추정 순수 추론 |
|---|---:|---:|---:|---:|
| Mi:dm Q4_K_M | **357.8** | 568.8 | 230.1 | **127.7** |
| Motif NF4 | **9,842.6** | 14,793.3 | 288.3 | 9,554.3 |

- **27.5배 차이.** Mi:dm은 원격 왕복을 포함해도 방송 리듬 목표(낭독→응답
  개시 ≤1,300ms, 리제 실측 중앙값 1,060ms)에 **3배 여유**. Motif는 케이스
  최장 14.7초 — 방송 사용 불가 수준.
- 바닥선(왕복+TLS+서버 오버헤드+1토큰) 230~288ms — Tailscale 경로 자체는
  가볍다. Motif 지연의 원인은 네트워크가 아니라 **추론 자체**(NF4
  bitsandbytes 경로의 낮은 처리량 + 2~5배 긴 출력).

### 출력 규격 (자동 마커 — 휴리스틱, 인간 검수 대체 아님)

| 지표 | Mi:dm | Motif |
|---|---:|---:|
| 자수 p50 / p95 | **32 / 103** | 166 / 260 |
| 10~45자 적중 | 23/38 (길이 규격 55%) | 0/38 (0%) |
| 3문장 초과 | 1건 | **37건** |
| 존댓말 응답(계약 위반) | 35건 | 37건 |
| 방송통과(복합) | 0% | 0% |

- **형식 규격은 Mi:dm 압승** — 리액션 길이 분포(관찰 연구의 "1~3초 조각"
  규격)에 자연 정렬. Motif는 전건 장황.
- Motif 고유 결함: `[YouTube]` 접두사를 응답에 누수(복수 관측), 문장 뒤
  잉여 "요." 꼬리, 동일 문장 반복 루프(사과 반복) — 아티팩트 수준 결함.
- **존댓말 위반은 양 모델 공통(35 vs 37)** — 시청자 채팅(존댓말)을
  미러링하는 raw 모델 경향. 이는 모델 변별점이 아니라 운영 프록시의
  스타일 게이트·재시도 계층이 잡는 문제다(로컬 proxy A/B에서 Mi:dm
  위반 0이었던 것과 정합). 단 방송 경로가 이 게이트를 거치도록 배선
  확인이 필요하다.

## 판정

**Mi:dm 유지 확정 권고.** 지연 27.5배·형식 규격·아티팩트 부재 — 세 축
모두에서 Motif NF4는 방송용 후보로 성립하지 않는다. 이는 dev PC의
네이티브 BF16 비교와 별개로, **실제 방송 운용 경로(8GB 양자화) 기준**의
판정이다.

## 부수 발견 (dev PC 원격 서버 계약)

1. **스트리밍 미지원** — `stream:true` → 400. 결정 2(방송 중 원격 LLM)
   시나리오에서 "첫 토큰부터 점진 재생" 전략을 쓰려면 스트리밍 지원
   추가가 선행 조건.
2. **max_tokens 상한** — 160 거부, 128 허용(경계 128~159 사이).
3. 무인증 401 정상 동작, 바닥선 230~288ms(Tailscale 왕복 경량) 확인.
