# B4c 방송 발화 계약 v3 — 수신자 자기 인지 축 + 검토 PC 로컬
실측 (2026-08-18, 검토 PC)

B4c 방송 발화 계약(`f0ff26e`)의 전/후 실측
(`완료/AIRI-B4C-CONTRACT-AB-2026-08-14.md`)에 이어, 사용자가 시뮬레이션
검토본 원문에서 직접 발견한 **수신자 자기 인지 실패** 축을 계약에
반영하고 검토 PC 로컬 Mi:dm으로 2회(v2·v3) 실측한 기록이다.

## 배경

사용자가 2026-08-15 시뮬레이션 검토본
(`진행중/AIRI-BROADCAST-SIMULATION-OUTPUT-REVIEW-2026-08-15.md`) 원문을
직접 검토하다 **수신자 자기 인지 실패**를 발견했다 — dn04는 생일
축하를 받는 입장인데 "생일 축하해!"로 반사했고, gr01은 "어디서
잘 찾으셨어요"라는 질문을 받고도 찾은 주체를 시청자로 돌렸으며
(행위 주체 반전), tk04는 부계정 의혹을 받고 "궁금해서 물어본
거지"류로 자백하듯 답했다.

전수 재검토로 4유형을 분류했다 — 수신 반전(receive_reversal)·
행위 주체 반전(agent_reversal)·상황·자기 존재 인지 실패
(situation_blind)·역방향 오귀속(third_party_absorb). 채점 사이드카
(`ollama-proxy/eval/broadcast_chat/addressee-checks.json`)로 정리하며
28건(8/12/5/3)으로 확정했다.

이 케이스들 다수는 자동 마커의 `broadcast_pass=true`(형식·어투는
합격 판정)임에도 수신자 인지는 틀렸다 — 예를 들어 gr01·gr03은
반말·길이 규격을 모두 지키고도 주체를 시청자로 돌리거나 자기
존재를 착각했다. **자동 마커 한계의 실증이자, 이 인간 검수
packet이 만들어진 목적 자체를 보여준다.** 이 축은 기존 G1a 3문제나
B4c 계약 v1/v2 어디에도 등록되지 않았던 신규 발견이다.

## 구성

검토 PC 로컬 실측 체계를 신설했다 —
`ollama-proxy/setup-midm-airi-model.ps1`로 dev PC와 동일 태그
`midm-airi:2.0-mini`를 로컬 생성했다(digest
`106cfaacc185aec489ccbddd82894d6558aac745444b844a73cef4ea450e9f6c`,
로컬 `ollama` API로 재확인 — 이 문서 작성 시점 기준). Ollama는
측정 세션 기동 시 0.32.6이었고 문서 작성 시점 확인은 0.32.14다
(세션 중 자동 업데이트 — digest 고정이라 모델 바이트는 동일).
GPU 없음 — **CPU 추론이므로 지연 수치는 방송 비대표이며
품질(마커) 축 전용으로만 쓴다.** 응답 분포도 8/14 원격 게이트웨이
실측과 다르다(동일 가중치·다른 실행 환경) — 이 문서의 OFF/ON
비교는 **동일 런(로컬) 환경 내에서만** 유효하다.

## 1. 구현 (2회 반복)

- **v2**(sha256 `5bf61236…`): 추상 수신자 규칙 4행을 계약 블록에
  추가했다(552자). addressee 사이드카 28케이스(4유형 8/12/5/3,
  기존 픽스처 원문은 무수정)를 채점 자산으로 만들고 단발·리허설
  양 러너에 채점 배선을 붙였다.
- **v3**(sha256
  `ec7a420912facea689209087966b13af17e9f81bdba540a83c56c70fb9b422c3`,
  600자, 로컬 재계산 일치 확인): v2 단발 실측에서 dn04(축하 반사)·
  gr01(주체 반전)이 그대로 재발함을 확인한 뒤, 추상 지시를 구체
  예시·해석 규칙형으로 교체했다.
  - "축하·응원·감사는 받는 사람으로 '고마워!'처럼 답해. '생일
    축하해'를 돌려주지 마."
  - "'~하셨어요?'는 네가 한 일을 묻는 거고 부탁도 네 몫이니
    '내가 ~했어'로 답해."
  - "부계정 의혹이나 놀림도 네가 받은 거니 '내가 왜?'처럼
    받아쳐. 했다고 인정하지 마."

  OFF 바이트·기존 7행(v1 관찰 연구 규범)·리허설 픽스처 SHA는 전부
  불변이다. dev PC 체크포인트에 편입된 회귀(exact fixture SHA·
  content-free evidence 검증 포함)는 로컬 재실행에서 PASS를
  유지했고, `test_broadcast_contract.py` +
  `eval/broadcast_chat/test_run_broadcast_rehearsal.py` 87건도 전부
  PASS했다(이 문서 작성 직전 재실행 — 87 passed, subtests 129건
  포함).

## 2. 실측 — 단발 38픽스처 (전 런 실패 0)

| 지표 | OFF | ON v2 | ON v3(2rep=76) |
|---|---:|---:|---:|
| length_fit | 29% | 63% | **70%** |
| banmal | 13% | 60% | **62%** |
| 방송통과(복합) | 3% | 29% | **38%** |
| 존댓말 위반 건수 | 33 | 15 | 29 |
| addressee 통과 | 11/13 (85%) | 11/13 (85%) | 20/26 (77%) |

- v3 addressee 실패 6건은 케이스 4종에서 나왔다 — dn04
  (receive_reversal) 2/2·gr01(agent_reversal) 2/2·
  tk04(agent_reversal) 1/2·gr03(situation_blind) 1/2.
- **결정 증거 — dn04 원문.** 계약 v3에 "'생일 축하해'를 돌려주지
  마"가 명시돼 있음에도, 2회 반복 모두 그대로 위반했다.
  - rep1: `생일 축하해!🎂`
  - rep2: `생일 축하해! 오늘은 정말 즐겁게 보내세요.`
- gr01·gr03도 `broadcast_pass: true`(형식·어투 합격)이면서
  addressee만 실패한 사례를 남겼다 — 예: gr03 rep2 응답
  `나도 이제 들어왔어~ 지금 뭐 하고 있었어?`는 반말·길이·되묻기를
  모두 지켰지만 자기가 방송 진행자라는 사실을 놓쳤다. §배경의
  "자동 마커 한계" 주장을 이 문서 자체 데이터로도 재확인한다.

## 4. 판정·후속

1. 계약 v3는 **문맥 있는 흐름(리허설)에서 수신자 실패를 사실상
   해소**했다(93~100%). 단발 첫 대면은 77%로 여전히 불안정하다 —
   프롬프트 계층 단독 개입의 상한을 실측한 것으로 읽는다.
2. 잔여(dn04·gr01류)는 결정론 계층 소관이다 — **G1a A4.2 고정
   렌더러 방향과 실측이 합류**한다. 후원은 B4a
   `donation_name_callout_request` + 고정 감사 렌더러로 원천
   차단하고, 경어 주체류(gr01류)는 C2 자기 상태 주입 이후로
   넘긴다.
3. 반말 앵커 복불복이 v3에서도 재현됐다 — 운영 proxy 스타일
   게이트가 여전히 필수라는 기존 결론을 강화한다.
4. 이모지 증가를 계속 주시한다 — 로컬 리허설 v3 19~20건으로,
   v2보다 늘고 두 시나리오 모두로 번졌다.
5. addressee 사이드카 28케이스는 이후 모든 계층 변화(A4.2·C2 등)
   전/후의 회귀 자산으로 재사용한다.
6. 운영 ON 채택·파라미터 확정은 여전히 사용자 확인을 경유한다
   (로드맵 원칙 불변 — 자동 승격 아님).
7. 자동 마커는 휴리스틱이다. 최종 채택은 응답 전문 인간 검수를
   대체하지 않는다.

## 5. 한계

- **CPU 로컬 실측**이다 — GPU 없는 검토 PC에서 돌았으므로 지연
  수치는 방송 비대표다. 응답 분포도 8/14 원격 게이트웨이 실측과
  달라(동일 가중치·다른 실행 환경), 이 문서의 OFF/ON 비교는 동일
  런 환경 내에서만 유효하다.
- 자동 마커·addressee 사이드카는 전부 휴리스틱이다 — 최종 채택은
  응답 전문 인간 검수를 대체하지 않는다.
- reps 1~2(단발)·시나리오 2건(리허설)이다 — 분산·표본 모두 작다.
  첫 턴 앵커 복불복은 시나리오 2건 표본에서만 관측됐다.
- addressee 사이드카는 사이드카에 등록된 케이스만 채점한다 —
  등록 밖 실패는 이 수치에 반영되지 않는다.
- 비스트리밍 측정이라 TTFT는 리허설에서 관측하지 않는다(v1
  한계와 동일).
