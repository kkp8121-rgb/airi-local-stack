# 임베딩 A/B — KURE-v1 vs BGE-M3 (2026-08-18, 클로드 PC)

## 결론

**두 모델은 이 평가셋에서 구분되지 않는다. 교체 근거 없음 — KURE-v1 유지.**
24개 질의 중 **단 1개**(`q19`)에서만 갈렸고 그 1개를 BGE-M3가 맞혔다.
불일치쌍이 1:0이라 유의성 판정 자체가 성립하지 않는다(McNemar 기준
p=1.0). 나머지 23개는 순위까지 동일하다.

리서치가 인용한 MemDelta 경고("임베딩만 바꿔도 시스템 순위가 뒤집힌다",
`참조/AIRI-MEMORY-TECH-RESEARCH-2026-08-18.md` §2-1)는 **이 스택에서는
재현되지 않았다.** 다만 이는 MemDelta가 틀렸다는 뜻이 아니라, AIRI가
이미 그 논문이 권하는 쪽(강한 한국어 임베더)을 쓰고 있어 **바꿀 여지가
없다**는 뜻에 가깝다 — KURE-v1은 애초에 BGE-M3를 한국어로 파인튜닝한
모델이라 두 모델이 거의 같은 행동을 보이는 것은 예상과도 부합한다.

## 1. 왜 새 평가셋을 만들었나

기존 `benchmark_memory_track.py --mode embedding` 픽스처는 **문서 4개·질의
3개**다. 임베더가 로드되는지 보는 스모크로는 충분하지만 강한 한국어 모델
둘을 가르지 못한다(둘 다 MRR 1.0이 나온다). 그래서
`ollama-proxy/eval/embedding_ab/korean_memory_recall_v1.json`을 새로 만들었다
— **문서 48개·질의 24개**, 4개 카테고리 각 6개.

| 카테고리 | 노리는 것 |
|---|---|
| `lexical` | 질의와 표면 토큰을 공유 — 기준선 |
| `paraphrase` | 내용어를 거의 공유하지 않음 — 어휘 매칭으로는 불가능 |
| `disambiguation` | 같은 속성을 가진 인물이 여럿(고양이를 키우는 사람 / 고양이 알레르기인 사람 / 강아지를 원하는 사람) |
| `supersede` | 옛 사실과 갱신된 사실이 공존, 질의가 어느 쪽인지 결정("지금 어디 살아?" vs "예전에 어디 살았어?") |

인물·후원·방송 이벤트는 전부 가공이다(실제 시청자 데이터 아님).

## 2. 실측

`run_embedding_ab.py`, CPU, 전체 코퍼스 코사인 랭킹, `normalize_embeddings=True`.

| 지표 | KURE-v1 | BGE-M3 |
|---|---:|---:|
| MRR | 0.9213 | **0.9421** |
| recall@1 | 0.875 | **0.9167** |
| recall@3 | 0.9583 | 0.9583 |
| recall@5 | 0.9583 | 0.9583 |
| 중앙 순위 | 1.0 | 1.0 |
| 질의 인코딩 p50 | 124.6 ms | **115.7 ms** |
| 질의 인코딩 p95 | 159.3 ms | **125.4 ms** |
| 코퍼스 48건 인코딩 | 1,545 ms | 1,685 ms |

카테고리별:

| 카테고리 | KURE-v1 MRR | BGE-M3 MRR |
|---|---:|---:|
| lexical | 0.9167 | 0.9167 |
| paraphrase | 0.8519 | 0.8519 |
| disambiguation | **1.0** | **1.0** |
| supersede | 0.9167 | **1.0** |

**차이의 전부**: `q19` "별빛수집가 지금 어디 살아?" — KURE-v1은
`c18`(예전에 부산에 살았다)을 1위, 정답 `c19`(올해 서울로 이사했다)를
2위로 놨다. BGE-M3는 정답을 1위로 놨다. 그 외 23개는 동률이다.

**두 모델 공통 실패 2건**(더 중요한 신호):

- `q03` "코드깎는노인 직업이 뭐야?" → 둘 다 `c21`(지금은 회사에 다닌다)을
  1위, 정답 `c07`(백엔드 개발자다)을 2위. "직업"이 소속 상태 문장에
  더 붙는다.
- `q11` "얼굴 나오는 방송이야?" → 둘 다 정답 `c41`(카메라는 쓰지 않고
  Live2D 모델만 띄운다)을 **9위**로 밀고 `c28`(방송 주제는 잡담과 기술
  이야기)을 1위로 올렸다. **암묵적 부정("카메라를 안 쓴다"가 "얼굴이 안
  나온다"의 답)** 을 두 임베더 모두 못 잡는다.

즉 남은 회상 실패는 임베더 선택이 아니라 **질의-사실 사이의 추론 간극**에
있다. 임베더를 바꿔서 얻을 것이 거의 없다는 것이 이번 실측의 실질적 결론이다.

## 4. 한계

- **표본 24개**다. 1건 차이는 노이즈와 구분되지 않는다. "BGE-M3가
  낫다"고 읽으면 안 된다.
- 평가셋은 **내가 작성한 합성 데이터**다. 라벨(어느 문서가 정답인지)도
  같은 사람이 정했으므로 라벨 편향이 있을 수 있다.
- **CPU 측정**이다. 지연 120ms대는 운영 대표값이 아니다(운영은 GPU,
  회상 예산 14.9ms 기준은 코덱스 GPU 실측).
- 실제 운영 경로(`memory_runtime` → `MemoryStore.retrieve`)가 아니라
  **순수 코사인 랭킹**만 잰다. 실제 회상은 여기에 FTS·시간 가중·게이트가
  더 붙으므로 이 수치가 그대로 운영 회상 품질은 아니다.
- 모델은 각 1회 로드·1회 인코딩이다(변동 측정 없음, `temperature` 개념
  없어 결정론적).

## 5. 권고

1. **임베더 교체 없음.** KURE-v1 유지. 재검토는 평가셋이 100질의 이상으로
   커지거나 운영 회상 로그가 쌓인 뒤에 한다.
2. 다음 회상 개선 지점은 임베더가 아니라 **암묵적 부정·속성 질의**다
   (`q11`·`q03` 유형). 리서치 §3-①의 bm25 도입(완료)과 결이 같은
   어휘·구조 보강, 또는 질의 확장이 후보다.
3. 이 평가셋을 **회귀 기준선**으로 쓴다 — 회상 경로를 바꿀 때마다 같은
   24문항을 돌려 MRR 하락을 감지한다.
