# B4c 방송 발화 계약 전/후 A/B — Mi:dm 원격 실측 (2026-08-14, 검토 PC)

사용자 지시: "검토 PC에서 할 수 있는 모든 것"을 진행하라는 배치 지시
아래, B4c 방송 발화 계약 greybox(`f0ff26e`)의 전/후 실측을 기록한다.

## 구성

- 경로: 검토 PC → Tailscale → dev PC raw 서버
  (`https://home.tail3687f8.ts.net:11439/v1`, 비스트리밍,
  `max_tokens=128`). 서버가 `stream:true`를 400으로 거부해
  auto-fallback으로 비스트리밍 전환했다(양 조건 동일).
- 모델: `midm-airi:2.0-mini` 단독 — 사용자가 로컬 LLM을 Mi:dm으로
  확정한 뒤(결정 6, `완료/AIRI-REMOTE-BROADCAST-CHAT-AB-2026-08-14.md`)의
  측정이며 Motif는 대상에서 제외했다.
- 프롬프트: 운영 `AIRI_SYSTEM_PROMPT` 원문(SHA-256 레포 일치 검증) +
  방송 프레임 + 계약 블록(369자, SHA-256 `913feecb…7e7b0f`). 계약
  블록은 `ollama-proxy/broadcast_contract.py`의 `_build_block()`
  실측 재계산 결과가 결과 JSON의 `prompt.contract_block_sha256`
  필드와 일치한다.
- **raw 서버 직접 호출이므로 운영 proxy 스타일 게이트는 미개입한다.**
  이 측정은 계약 블록(모델 지시) 단독 효과를 격리 관찰한 것이며,
  운영 배선(프록시 스타일 게이트 경유)에서의 결과와는 다를 수 있다.
- 러너: `run_broadcast_chat_ab.py --contract on/off`(단발
  38픽스처), `run_broadcast_rehearsal.py --contract on/off`(멀티턴
  2시나리오×24턴). 원 응답 전문:
  `ollama-proxy/eval/results/broadcast-chat-b4c-{off,on}-2026-08-14.json`,
  `broadcast-rehearsal-{off,on}-2026-08-14.json`.

- OFF는 두 시나리오 모두 존댓말 위반 24/24(`v_polite_response`)·
  반말 0% — 히스토리 되먹임으로 존댓말 미러링이 보편화됐다(단발
  8%보다 악화).
- ON은 **첫 턴 앵커 고정** 현상을 보였다. game_and_career는 반말
  100%·no_violation 100%·방송통과 71%·태그의문 33%로 계약이
  작동했지만, autumn_leaves는 첫 턴이 존댓말로 앵커되자 24턴 내내
  존댓말에 잠겼다(length_fit만 62%→100%로 개선했을 뿐 어투는
  바뀌지 않았다).
- 시사점: **계약(모델 지시)만으로는 멀티턴 앵커를 보증하지 못한다.**
  운영 proxy 스타일 게이트(치환 + 미해결 존댓말 문장 드롭)가
  히스토리 앵커를 반말로 고정하는 역할을 겸하므로, 계약 블록과
  스타일 게이트의 이중 배선이 설계상 정합이다(`AIRI-ROADMAP-STATUS.md`
  '스타일 게이트 방송 경로 배선 확인' 항목과 연결).

- 콜백(창안) 1/1은 OFF/ON 공통 — 문맥 내 콜백 자체는 계약과 무관하게
  동작한다.
- 콜백(창밖) 0/1은 OFF/ON 공통 실패 — 8쌍 히스토리 캡 밖으로 밀린
  probe는 계약 유무와 무관하게 놓쳤다. **시청자 기억(I2) 연동의
  필요성을 실증한다.**
- 여론 집계는 OFF 3/4(autumn_leaves 2/2, game_and_career
  1/2)→ON 4/4(양 시나리오 2/2)로 소폭 개선했다.
- 후원 호명은 0/2로 OFF/ON 공통 미달 — 계약 문구가 "후원에만
  불러"로 **허용**만 하고 의무화하지 않은 결과로 읽힌다(§4 조정
  후보).
- 멀티턴 완료 지연은 ON 기준 p50 340.1~371.2ms·p95 378.1~399.8ms —
  낭독→응답 개시 목표 상한 1,300ms(관찰 연구 §6) 대비 3배 이상
  여유를 유지했다.

## 4. 판정·후속

- **계약 블록 효과는 단발 기준으로 실증됐다** — 방송통과 0%→50%,
  반말 8%→66%, 존댓말 위반 35→13건 등 게이트 없이도 전 마커가
  개선됐다.
- 단, 다음 항목은 후속이 필요하다.
  1. **멀티턴 앵커는 계약 단독으론 불충분** — 운영 배선에서는 반드시
     proxy 스타일 게이트를 경유해야 한다. canonical source patch의 exact
     11435 정적 계약은 checkpoint에 고정했고, B1b 실제 AIRI 주입 때
     모델 출력→스타일 게이트→public wire/TTS 종단 실증을 수행한다
     (`AIRI-ROADMAP-STATUS.md`의 B1b 조건부 라이브 실증 항목과 연결).
  2. **이모지 소폭 증가 주시** — 단발 1→3건, 멀티턴 ON
     autumn_leaves에서도 1건 추가 발생.
  3. **후원 호명은 B4a action으로 의무화** — 계약 문구는 그대로 두고
     디렉터가 `donation_name_callout_request`를 내도록 명시했다. 실제 1회
     호명 강제와 리허설은 B4b adapter 완료 조건이다.
  4. **파라미터 확정·운영 ON 채택은 사용자 확인을 경유한다**
     (로드맵 원칙 유지 — 자동 승격 아님).
  5. **창밖 콜백 미스는 I2(시청자 기억) 연동이 필요**하다.
- 자동 마커는 휴리스틱이다. 최종 채택은 응답 전문 인간 검수를
  대체하지 않는다.

## 5. 한계

- 비스트리밍 측정이라 TTFT 미측정 — 완료 시간 기준으로만 분해했다.
- reps=1(반복 분산 미측정) — 완료 p50/p95는 38케이스(단발)·
  시나리오당 24턴(멀티턴) 분포 기준이다.
- **raw 서버 직접 호출 경로**다 — 운영 proxy의 스타일 게이트가
  미개입이므로, 이 결과는 계약 블록 단독 효과이지 운영 배선 전체의
  효과가 아니다.
- 멀티턴 리허설은 채팅 낭독(TTS 음성)이 없는 **텍스트 시뮬레이션**이다
  — '낭독→응답 원자화'의 텍스트 근사만 측정하며 실제 음성 타이밍·
  침묵 예산·오디오 베드 효과는 재지 않는다.
- 첫 턴 앵커 현상은 **시나리오 2건 표본**에서 관측됐다 — 일반화
  이전에 추가 시나리오로 재현 확인이 필요하다.
