# AIRI EXAONE 3.5 모델 커스터마이징 기술 계획

- 작성일: 2026-08-07 (KST)
- 상태: 장기 연구 트랙, 즉시 구현 아님
- 기준 모델: `LGAI-EXAONE/EXAONE-3.5-2.4B-Instruct`
- 현재 런타임 태그: `exaone-airi:2.4b`
- 상위 전략: [AIRI-EXAONE-GROWTH-STRATEGY-2026-08-07.md](./AIRI-EXAONE-GROWTH-STRATEGY-2026-08-07.md)

## 1. 목적

EXAONE 3.5 2.4B를 AIRI의 빠른 한국어 언어 코어로 유지하면서 다음 두 방향의 모델 커스터마이징 가능성을 관리한다.

1. **추가**: AIRI 말투, 감정, 행동, 도구 사용과 방송형 반응을 LoRA/QLoRA로 특화한다.
2. **축소**: 실제 병목이 확인된 경우에만 레이어·MLP·Attention·어휘 구조를 실험적으로 줄인다.

이 계획은 EXAONE 안에서 “불필요한 지식만 골라 삭제”하는 것을 목표로 하지 않는다. 밀집형 언어 모델의 지식과 언어 능력은 같은 가중치에 분산되어 있으므로, 특정 지식 영역을 잘라내면 한국어·추론·대화 품질까지 함께 손상될 수 있다.

## 2. 확정 결정

- 현재 Q4_K_M 모델과 운영 스택은 기준선으로 보존한다.
- 모델 수정은 현재 캐릭터 루프·장기 기억·평가 데이터 구축을 방해하지 않는 별도 연구 트랙으로 운영한다.
- 첫 모델 수정은 구조 프루닝이 아니라 성격 LoRA/QLoRA다.
- 사용자 개인 기억과 최신 사건은 모델 가중치에 넣지 않는다.
- 자동 온라인 학습은 하지 않는다.
- 구조 축소는 속도 또는 메모리 병목이 평가로 확인된 경우에만 시작한다.
- 모든 파생 모델은 원본과 나란히 보관하며 언제든 기준 모델로 되돌릴 수 있어야 한다.
- 수정 모델은 `EXAONE-AIRI-3.5-2.4B-vN`처럼 `EXAONE`으로 시작하는 이름을 사용한다.

## 3. 현재 모델과 실행 경로

EXAONE 3.5 2.4B 공식 구성의 주요 값은 다음과 같다.

| 항목 | 값 |
|---|---:|
| Transformer 블록 | 30 |
| hidden size | 2,560 |
| MLP intermediate size | 7,168 |
| Attention Q heads | 32 |
| KV heads | 8 |
| head dimension | 80 |
| vocabulary | 102,400 |
| 최대 context | 32,768 |
| 입력·출력 embedding | 공유 |

현재 `exaone-airi:2.4b`는 GGUF Q4_K_M 가중치를 Ollama가 llama.cpp 계열 런타임으로 실행한다. 이 경로에서는 Hugging Face의 `modeling_exaone.py`를 수정해도 현재 Ollama 실행 결과가 바뀌지 않는다.

수정 종류별 실제 반영 경로는 다음과 같다.

| 수정 | 작업 위치 | 현재 Ollama 반영 방법 |
|---|---|---|
| 시스템 프롬프트·stop·sampling | Modelfile 또는 proxy | 런타임 설정 변경 |
| 대화 디렉터·기억·도구 검증 | proxy와 외부 서비스 | 모델 파일 변경 없음 |
| LoRA/QLoRA | Hugging Face 원본 + PEFT | 평가 후 merge/변환/양자화 |
| 레이어·MLP 구조 변경 | config·model code·weights | 회복 학습 후 GGUF 변환기 호환 확인 |
| Attention 구현 변경 | Transformers 또는 llama.cpp/Ollama | 해당 런타임을 별도로 빌드 |
| tokenizer/어휘 변경 | tokenizer + embedding + LM head | 전체 토큰 ID 호환성 재검증 후 변환 |

## 5. AIRI에 추가할 능력의 경계

### 5.1 LoRA에 학습할 것

- 한국어 반말과 AIRI 고유 말투
- 빠른 방송 대화를 위한 짧은 첫 문장
- 맞장구, 되묻기, 농담과 실수 복구
- 같은 표현의 반복 억제
- 감정 변화와 ACT 토큰 사용
- 관계 단계에 맞는 거리감과 표현
- 도구 사용 전후의 정직한 표현
- 말하기, 기다리기, 질문하기 같은 행동 표현
- 답을 모를 때 허위 사실보다 확인이나 질문을 선택하는 행동

### 5.2 외부 기억·상태에 남길 것

- 사용자 이름과 개인정보
- 개인 취향과 약속
- 최근 사건과 방송 에피소드
- 관계와 감정 상태의 현재 값
- 도구 실행 결과와 게임 상태
- 수정·삭제가 필요한 사실

### 5.3 별도 모듈에 남길 것

- STT·TTS·Live2D 제어
- 화면·비전 인식
- 게임 상태 수집과 저수준 조작
- 도구 실행 권한과 안전 경계
- 응답 선택·취소·타임아웃
- 영구 기억 저장 여부 판정과 개인정보 정책

## 6. 연구 단계와 게이트

### C0. 기준선과 평가 세트 고정

시작 시점: G1 캐릭터 루프와 G2 기억 경계가 정해진 뒤.

필수 산출물:

- 기준 GGUF의 해시, Modelfile과 runtime 설정
- 한국어 일반 대화 세트
- AIRI 성격·말투 세트
- 반복·되묻기·실수 복구 세트
- 기억 있음/없음 대조 세트
- ACT 토큰과 도구 출력 계약 세트
- 환각·도구 거짓말·안전 회귀 세트
- TTFT, 출력 토큰 속도, RAM·VRAM 기준선

게이트:

- 동일 입력을 같은 설정으로 반복 측정할 수 있다.
- 모델, 프롬프트, 메모리와 proxy 변화의 효과를 분리해 판정할 수 있다.

### C1. 성격 SFT LoRA

입력 데이터:

- 검수된 AIRI 대화
- 개발자가 수정한 이상적 답변
- 캐릭터 경계를 지키는 반례와 복구 예제
- 기억 블록을 자연스럽게 사용하되 그대로 낭독하지 않는 예제

원칙:

- 양보다 품질을 우선한다.
- 동일한 표현을 과도하게 복제하지 않는다.
- 학습·검증·시험 데이터를 분리한다.
- 테스트 세트와 실제 사용자 대화 원문을 무단 학습하지 않는다.
- LoRA를 먼저 평가하고 기준 모델에 바로 병합하지 않는다.

중단 조건:

- 존댓말·반말 혼용 또는 상투 문구가 기준보다 증가한다.
- 일반적인 한국어 이해와 질문 응답이 유의미하게 저하된다.
- 기억이 없는 상황에서 거짓 기억을 생성하는 경향이 증가한다.
- ACT·JSON·도구 출력 형식 회귀가 발생한다.
- 짧은 답변 특화가 무반응·단답 고착으로 변한다.

### C2. 선호 학습

시작 조건:

- 충분한 `선택 응답 / 거절 응답 / 선택 이유` 쌍이 축적됐다.
- SFT 모델이 기준 회귀 시험을 통과했다.

목표:

- 더 AIRI다운 응답 선택
- 반복과 장문의 억제
- 자연스러운 되묻기와 침묵
- 실제 도구 실행 여부에 맞는 표현
- 감정·관계 상태에 맞는 반응

선호 데이터가 부족한 단계에서 DPO를 먼저 시작하지 않는다.

### C3. 선택적 제어 토큰

현재 텍스트 기반 `<|ACT ...|>` 계약은 이미 정상 동작하므로 기본 tokenizer를 유지한다.

다음 문제가 반복적으로 평가될 때만 학습 토큰 추가를 검토한다.

- ACT 구문 파싱 실패
- 감정과 행동 토큰의 잦은 누락
- 토큰 문자열을 음성으로 읽는 회귀
- 복합 행동에서 구조화 출력이 안정되지 않음

새 토큰을 추가하면 tokenizer, embedding, LM head, GGUF 변환과 기존 대화 로그의 토큰 호환성을 함께 시험한다.

### C4. 구조 프루닝 연구

시작 조건:

- C1/C2 모델과 안정된 평가 세트가 있다.
- 실제 병목이 LLM 연산 또는 메모리라는 계측 결과가 있다.
- 별도 실험 브랜치와 원본 체크포인트가 있다.

권장 순서:

1. 각 레이어를 일시적으로 마스킹하여 민감도를 측정한다.
2. 한 번에 1~2개 레이어만 제거한 후보를 만든다.
3. config와 state dict를 새 구조에 맞춘다.
4. LoRA 또는 제한된 회복 학습을 수행한다.
5. 기준·성격·기억·도구·지연 평가를 모두 실행한다.
6. 이득이 확인된 경우에만 다음 축소 단계를 시도한다.

초기 후보는 `30 → 28 → 26` 블록처럼 보수적으로 진행한다. 처음부터 24개 이하로 크게 줄이지 않는다.

MLP와 Attention 프루닝은 레이어 삭제보다 뒤에 둔다. 단순한 희소 mask는 Ollama에서 실제 속도 향상을 보장하지 않으므로, 런타임이 지원하는 더 작은 밀집 구조로 재작성할 수 있을 때만 채택한다.

구조 프루닝 중단 조건:

- 한국어·성격 평가가 LoRA로 회복되지 않는다.
- 속도 또는 메모리 이득이 측정 오차 수준이다.
- GGUF 변환이나 Ollama 런타임에 지속적인 커스텀 패치가 필요하다.
- TTS·STT를 포함한 종단 첫 음성 지연이 개선되지 않는다.
- 유지보수 비용이 향후 기반 모델 교체 비용보다 커진다.

### C5. Ollama 배포

1. 학습 또는 구조 수정 모델을 Transformers 경로에서 평가한다.
2. 필요하면 LoRA를 병합하되 미병합 어댑터도 보관한다.
3. 지원되는 변환기를 사용해 BF16 GGUF를 생성한다.
4. Q5_K_M과 Q4_K_M을 우선 비교한다.
5. 한국어 품질 때문에 Q3 이하를 기본 배포 후보로 사용하지 않는다.
6. 별도 Ollama 태그로 등록하고 기존 `exaone-airi:2.4b`를 덮어쓰지 않는다.
7. proxy와 AIRI 설정에서 명시적으로 후보 태그를 선택하여 A/B 시험한다.

예시 이름:

```text
EXAONE-AIRI-3.5-2.4B-v1-lora
EXAONE-AIRI-3.5-2.4B-v1-q4km
EXAONE-AIRI-3.5-2.4B-v1-pruned28-q4km
```

## 7. 하드웨어 원칙

- 현재 Q4 Ollama 파일을 직접 학습 대상으로 사용하지 않는다.
- Hugging Face 원본 가중치와 PEFT/QLoRA 경로를 사용한다.
- RTX 3060 Ti 8GB에서는 작은 batch, 제한된 sequence, gradient accumulation과 checkpointing이 필요할 가능성이 높다.
- 학습 중에는 운영 Ollama·STT·TTS의 동시 상주를 전제로 하지 않는다.
- 먼저 아주 작은 데이터와 짧은 sequence로 VRAM 게이트를 측정한다.
- 구조 프루닝의 회복 학습이 8GB 환경에서 비현실적이면 느린 CPU offload에 매달리지 말고 별도 GPU·클라우드 또는 연구 보류를 선택한다.
- 학습 환경과 실시간 AIRI 운영 환경을 분리한다.

## 9. 소스 코드 수정 원칙

- 공개된 Transformers EXAONE 구현을 수정할 때 자동 생성 파일을 직접 고치지 않고 원본 modular 구현을 수정한다.
- 현재 Ollama에 영향을 주려면 llama.cpp/Ollama 실행 경로의 지원 여부를 별도로 확인한다.
- 모델 구조를 바꿀 때 config 값만 수정하고 기존 가중치를 억지로 로드하지 않는다.
- 구조, tokenizer와 weight mapping 변경은 변환 전용 시험을 둔다.
- upstream과 큰 차이가 생기는 커스텀 런타임은 마지막 수단으로 둔다.
- 각 실험은 별도 브랜치·체크포인트·모델 태그에서 진행하고 현재 운영 모델을 덮어쓰지 않는다.

## 12. 메인 개발 세션의 실행 지침

현재 세션이 수행할 일:

1. 이 문서를 장기 연구 트랙으로 인식한다.
2. 현재 작업 트리의 memory 구현과 캐릭터 연속성 작업을 우선한다.
3. 모델 커스터마이징을 바로 구현하지 않는다.
4. G3 평가·데이터 설계 시 이 문서의 C0 평가 항목을 포함한다.
5. 파인튜닝 시작 요청이 생기면 C0 게이트부터 계획을 재검토한다.
6. 구조 축소 요청이 생기면 C1 결과와 LLM 병목 계측이 있는지 먼저 확인한다.

모델 커스터마이징 트랙의 첫 실제 산출물은 학습 코드가 아니라 **재현 가능한 기준 평가 세트와 결과표**다.

## 13. 결론

EXAONE 3.5는 AIRI용으로 수정할 수 있다. 그러나 현재 가장 가치 있는 수정은 모델 내부를 잘라내는 것이 아니라, 원본을 보존하면서 AIRI 성격과 행동을 LoRA로 추가하는 것이다. 구조 프루닝은 캐릭터·기억·평가 체계가 안정되고 LLM 자체가 병목으로 입증된 뒤 진행한다.

> **추가는 LoRA 우선, 기억은 외부 계층, 구조 삭제는 계측 후 연구, 원본 모델은 항상 보존한다.**
