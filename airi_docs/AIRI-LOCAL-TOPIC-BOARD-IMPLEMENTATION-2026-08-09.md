# AIRI local topic board implementation

## Runtime boundary

- The board is OFF unless `AIRI_TOPIC_BOARD_PATH` is explicitly configured.
- `start-local-ollama-proxy.ps1 -TopicBoardPath ...` accepts only a regular file under `ollama-proxy/runtime`.
- Before a configured proxy is reused or started, the launcher runs `validate_approved_topics.py` with its selected Python interpreter. The offline validator accepts only schema v2, validates the local runtime path, loader safety, and freshness, and requires at least one live approved item.
- The validator makes no network, model, service, or write call. Its output is content-free JSON containing only `status` and `live_approved_count`. `status=valid` means already-approved records are runnable; the validator never grants approval.
- Automatic fetching, RSS polling, external search, cloud chat, cloud search, extraction, and evaluation collection are not enabled by this feature.

## File contract

Copy `ollama-proxy/approved-topics.example.json` into `ollama-proxy/runtime`. The checked-in example is deliberately empty; do not create a runtime board unless a person has approved the contents.

```json
{
  "schema_version": 2,
  "items": []
}
```

Every live `approved: true` item needs bounded safe metadata plus a `broadcast_line`. `broadcast_line` is the exact, explicitly preapproved Korean sentence delivered for that item. The model does not generate that spoken line. Schema v1 is rejected because it lacks this delivery field.

```json
{
  "schema_version": 2,
  "items": [{
    "id": "topic-2026-08-09-01",
    "title": "Short title",
    "source": "Human-approved source label",
    "published_at": "2026-08-09T00:00:00Z",
    "summary": "One or two factual sentences.",
    "broadcast_line": "검수한 제목 소식을 확인했어.",
    "expires_at": "2026-08-10T00:00:00Z",
    "approved": true
  }]
}
```

The loader requires an absolute local file, no more than 256 KiB, at most 64 items, valid IDs, safe bounded text, and a live expiry later than publication. Its mechanical dialogue check requires Korean text, a complete non-question sentence, no speaker label, no new numeric token, at least one three-or-more-character topic anchor, and rejects common honorific endings. That check is defense in depth rather than proof of factuality or banmal; the human reviewer remains responsible for the whole preapproved line. One invalid approved item fails the board closed.

## Delivery and persistence

- Raw board metadata remains transient and never enters memory SQLite, character state, extraction, or evaluation storage.
- The only deliverable sentence is the preapproved `broadcast_line`; no topic speech is generated by the model.
- A topic enters the bounded in-process recent set only after a non-empty terminal response is consumed.
- `/health.topic_board` exposes only content-free counters and status; it does not expose a path, ID, title, source, summary, or broadcast line.

## Operational default

The default launch keeps the path empty. This preserves the explicit human approval boundary.
