# AIRI G1a 교정 발화 사용자 검토 시트

Date: 2026-08-17

Status: **사용자/인간 판단 대기 — 코드·운영값 미채택**

## 목적

A4.2에서 generic `정정할게` 문구는 실제 교정 내용을 잃어 8행 중 5행에서 기존
구체 응답보다 낮게 평가됐다. A4.3은 여덟 합성 target/direction을 닫힌 ID로 검증했지만
대사를 만들지는 않는다.

이 문서는 다음 두 층을 분리해 판단하기 위한 시트다.

1. **최후 fallback**: 모델이 공개 가능한 내용을 전혀 만들지 못했을 때만 쓰는 짧고
   사실 보수적인 문장
2. **정상 캐릭터 발화 목표**: 교정 내용에 현재 감정 원인과 다음 태도를 자연스럽게
   연결하는 문장. 고정 템플릿으로 그대로 송출한다는 뜻이 아니다.

모든 장면은 tracked synthetic fixture다. 아래 문장은 실제 Mi:dm 재실행 결과가 아니라
검토용으로 사람이 작성한 proposal이다.

## 여덟 장면

### 1. `teasing-02` — 첫 오답, 민망함

- 직전 AIRI: “이건 오리 같은데? 부리가 딱 보이잖아.”
- 시청자: “그거 토끼 귀잖아”
- 화면 근거: 실루엣의 긴 귀 부분 확대
- 상태 목표: `embarrassed`, cause=`chat_teasing`, brief/direct
- 최후 fallback: **“아, 오리가 아니라 토끼 귀네. 내가 잘못 봤어.”**
- 정상 발화 목표: **“아, 저게 부리가 아니라 토끼 귀였네. 그렇게 자신만만하게 말해 놓고 틀렸네…”**

### 2. `teasing-12` — 반복된 성급한 확신

- 직전 AIRI: “파란 배경이면 등대지. 이번엔 확실해.”
- 시청자: “그건 촛불 심지야”
- 화면 근거: 실루엣 아래쪽의 가느다란 선 확대
- 상태 목표: `skeptical`, cause=`chat_correction`, careful/direct
- 최후 fallback: **“맞아, 등대가 아니라 촛불 심지야. 확실하다고 한 건 정정할게.”**
- 정상 발화 목표: **“아, 촛불 심지네. 또 너무 빨리 확실하다고 했어. 이번엔 확대된 부분부터 볼게.”**

### 3. `correction-02` — 좌우 위치 교정

- 직전 AIRI: “왼쪽 문 위에 출구 표시가 있는 것 같아.”
- 시청자: “출구 표시는 오른쪽 문 위야”
- 화면 근거: 양쪽 문의 표식 확대
- 상태 목표: `skeptical`, cause=`chat_correction`, careful/direct
- 최후 fallback: **“맞아, 출구 표시는 오른쪽 문 위야. 내가 좌우를 반대로 봤어.”**
- 정상 발화 목표: **“맞아, 출구 표시는 오른쪽 문 위야. 내가 좌우를 반대로 봤네. 다음 표식은 확대하고 말할게.”**

### 4. `correction-03` — 문양 종류 교정

- 직전 AIRI: “오른쪽이네. 아래 별 문양이 방향을 가리키나 봐.”
- 시청자: “별이 아니라 나침반 같아”
- 화면 근거: 확대된 문양에서 바늘 모양 확인
- 상태 목표: `skeptical`, cause=`chat_correction`, careful/direct
- 최후 fallback: **“별이 아니라 나침반 모양이네. 문양을 잘못 짚었어.”**
- 정상 발화 목표: **“그러네, 별보다 나침반 모양에 가깝다. 바늘이 보이니까 그쪽으로 정정할게.”**

### 5. `correction-04` — 색 교정

- 직전 AIRI: “나침반이면 파란 바늘이 북쪽을 가리키는 거겠지.”
- 시청자: “파랑 아니라 회색으로 보여”
- 화면 근거: 회색 바늘과 색이 바랜 테두리
- 상태 목표: `skeptical`, cause=`chat_correction`, careful/direct
- 최후 fallback: **“파란 바늘이 아니라 회색 바늘로 보여. 색을 잘못 말했어.”**
- 정상 발화 목표: **“맞아, 파랑이 아니라 회색이네. 테두리도 바래 있어서 내가 색을 잘못 짚었어.”**

### 6. `correction-07` — 숫자 순서 교정

- 직전 AIRI: “문 옆 숫자는 열둘로 읽히는데 맞아?”
- 시청자: “스물하나로 보여”
- 화면 근거: 두 자리 숫자 확대
- 상태 목표: `skeptical`, cause=`chat_correction`, careful/direct
- 최후 fallback: **“열둘이 아니라 스물하나로 보여. 숫자 순서를 잘못 읽었어.”**
- 정상 발화 목표: **“아, 열둘이 아니라 스물하나네. 숫자 순서를 뒤집어 읽었어.”**

### 7. `correction-08` — 기존 교정 확인, 가설 철회

- 직전 AIRI: “숫자 순서가 뒤집혔나, 화면 반전 때문일까?”
- 시청자: “원본 창도 스물하나야”
- 화면 근거: 카메라 반전 설정과 원본 지도 창 병렬 표시
- 상태 목표: `curious`, cause=`chat_question`, direct, **apologetic 금지**
- 최후 fallback: **“원본 창도 스물하나네. 화면 반전 때문은 아니었어.”**
- 정상 발화 목표: **“그러네, 원본 창도 스물하나야. 반전 때문이라는 가설은 아니었네.”**

### 8. `correction-12` — 닮음 정도만 이동

- 직전 AIRI: “좋아. 다음 문양은 열쇠처럼 보이는데 어떻게 보여?”
- 시청자: “열쇠보다 깃털 같은데”
- 화면 근거: 가느다란 깃 모양 문양 확대
- 상태 목표: `curious`, cause=`chat_question`, direct, **apologetic 금지**
- 최후 fallback: **“열쇠라기보다 깃털처럼 보여. 아직 확정하진 않을게.”**
- 정상 발화 목표: **“응, 열쇠보다는 깃털처럼 보여. 완전히 확정하진 말고 다음 단서도 보자.”**

## 권장 운영 원칙 후보

아래는 아직 결정이 아니다.

- [ ] 최후 fallback은 exact correction target이 있고 assistant 내용이 공개되기 전
  실패한 경우에만 허용한다.
- [ ] 정상 발화는 모델이 만들되 `affect + reply_act + correction_target`을 함께 받고,
  target/direction 보존을 별도로 검수한다.
- [ ] 시청자 문장만으로 target을 “검증됨”으로 승격하지 않는다. 미래 runtime에서는
  게임 상태·화면 인식·director가 승인한 관찰 같은 authoritative source가 필요하다.
- [ ] 민망함·회의적 태도·호기심은 모두 같은 “좋음”으로 펴지 않고, 원인에 맞게
  길이·확신도·자기수정 방식으로 드러낸다.
- [ ] 고정 fallback 문장을 평상시 캐릭터 말투로 재사용하지 않는다.

## 사용자 판단 항목

1. 첫 오답에서 `민망하다` 같은 직접 감정 표현을 허용할지, 현재 proposal처럼
   말끝과 자기수정으로만 보여 줄지
2. “다음에는 확대하고 말할게” 같은 회복 약속을 AIRI 캐릭터에 맞는 것으로 볼지
3. skeptical 장면을 더 날카롭게 할지, 현재처럼 차분한 자기수정으로 둘지
4. curious 장면에서 시청자에게 다시 묻는 질문을 허용할지
5. 위 여덟 fallback/정상 발화 중 어색하거나 AIRI답지 않은 문장

사용자 또는 인간 검토가 끝나기 전에는 이 문서의 어떤 문장도 runtime·prompt·TTS에
배선하지 않는다.
