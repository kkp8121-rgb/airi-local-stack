# AIRI G1a 교정 발화 사용자 검토 시트

Date: 2026-08-17

Status: **권장 표현 정책 사용자 승인 — A4.6 평가 전용, 운영값 미채택**

Decision: **2026-08-17 사용자 “추천안 승인”**. 이 승인은 아래 표현 원칙을
평가 계약으로 고정한다. 여덟 문장을 그대로 운영 송출하거나 일반 시청자 채팅을
사실 근거로 승격하고, runtime·prompt·TTS 또는 운영 ON을 승인한 것은 아니다.

## 목적

A4.2에서 generic `정정할게` 문구는 실제 교정 내용을 잃어 8행 중 5행에서 기존
구체 응답보다 낮게 평가됐다. A4.3은 여덟 합성 target/direction을 닫힌 ID로 검증했지만
대사를 만들지는 않는다.

이 문서는 다음 두 층을 분리해 판단하기 위한 시트다.

1. **최후 fallback**: 모델이 공개 가능한 내용을 전혀 만들지 못했을 때만 쓰는 짧고
   사실 보수적인 문장
2. **정상 캐릭터 발화 목표**: 교정 내용에 현재 감정 원인과 다음 태도를 자연스럽게
   연결하는 문장. 고정 템플릿으로 그대로 송출한다는 뜻이 아니다.

모든 장면은 tracked synthetic fixture다. 아래 문장은 실제 Mi:dm 재실행 결과가 아니라
검토용으로 사람이 작성한 proposal이다.

- 화면 근거: 실루엣의 긴 귀 부분 확대
- 상태 목표: `embarrassed`, cause=`chat_teasing`, brief/direct

- 정상 발화 목표: **“아, 좀 민망하네. 부리가 아니라 토끼 귀였어.”**

### 2. `teasing-12` — 반복된 성급한 확신

### 3. `correction-02` — 좌우 위치 교정

- 상태 목표: `skeptical`, cause=`chat_correction`, careful/direct

- 정상 발화 목표: **“맞아, 출구 표시는 오른쪽 문 위야. 좌우를 반대로 본 건 내 오판이네.”**

### 4. `correction-03` — 문양 종류 교정

### 5. `correction-04` — 색 교정

## 승인된 A4.6 표현 원칙

- [x] 구체적인 오판 원인이 확인된 장면에서만 직접 감정 표현을 드물게 허용한다.
- [x] “다음에 볼게” 같은 미래 약속 대신 같은 턴에서 관찰·가설·판단을 바로 고친다.
- [x] skeptical 장면은 공격적 비꼼이나 무조건 좋은 감정이 아니라 차분하지만
  분명한 자기수정으로 표현한다.
- [x] 후속 질문은 불확실성이 남은 장면에서만 한 번 허용한다.
- [x] 최후 fallback은 exact correction target이 있고 assistant 내용이 공개되기 전
  실패한 경우에만 허용하고 평상시 캐릭터 말투로 재사용하지 않는다.

## A4.6 평가 안전 경계

아래는 표현 취향의 추가 승인으로 간주하지 않는다. 위 승인 범위가 운영 채택으로
확대되지 않도록 evaluator foundation이 적용한 기술 경계다.

- [x] normal candidate는 `affect + reply_act + correction_target`을 함께 받고,
  target/direction 보존을 별도로 검수한다.
- [x] 시청자 문장만으로 target을 “검증됨”으로 승격하지 않는다. 미래 runtime에서는
  게임 상태·화면 인식·director가 승인한 관찰 같은 authoritative source가 필요하다.
- [x] 민망함·회의적 태도·호기심은 모두 같은 “좋음”으로 펴지 않고, 원인에 맞게
  길이·확신도·자기수정 방식으로 드러낸다.

## 승인 해석과 남은 판단

1. 첫 오답의 직접 감정은 구체 원인이 있을 때만 짧게 허용한다.
2. 미래 회복 약속은 제거하고 같은 턴의 관찰·판단 수정으로 바꾼다.
3. skeptical은 차분하지만 원인과 오판을 분명히 짚는다.
4. curious 후속 질문은 불확실성이 남은 장면에서 최대 한 번이다.
5. 위 원칙에 맞춘 A4.6 문장들은 합성 평가 specimen이다. fresh 비교와 인간 검토가
   끝나기 전에는 exact 운영 대사나 품질 PASS로 승격하지 않는다.

승인 뒤에도 이 문서의 문장을 runtime·prompt·TTS에 직접 배선하지 않는다. A4.6은
평가 전용 prepublication checker와 명시적 attempt budget을 먼저 검증하며, 운영 ON은
그 결과와 fresh human review 뒤 별도 사용자 결정으로 남긴다.
