## 5. 오늘 새로 생긴 규칙과 함정

- **보관용 규율**: 규칙을 고치는 사람은 카드·대본·채점 메모를 읽지 않는다. 시청자 역할은 Sonnet 에이전트(VIEWER.md, 명령을 한 번에
  하나씩), 채점은 버전을 모르는 Opus 에이전트 두 명(JUDGE.md), 대본 라벨은 중립 이름(X1·X2). 방송마다 스택을 새로 띄운다.
- **큰 판정 모델을 아이리 옆에 둘 때**(memory `judge-model-next-to-stack`): 미리 올려 둔다(안 그러면 프록시 4초 제한에 매번 끊겨 영영
  못 올라온다 — J1 첫 시도 무효). 8비트판은 GPU에 올리면 아이리 모델과 기억 검색 모델을 밀어내고, CPU에 두면 RAM 9.4GB를 써서
  사용자 작업과 부딪힌다. 4비트판을 GPU 층 11개로 두면 밀어내지 않는다 — 올린 뒤 프로세스별 전용 VRAM으로 확인한다.
- 변이 검사 스크립트는 `SUBFAILED` 줄과 「N failed」 요약을 센다(`FAILED`만 세면 잡힌 변이가 살아남은 것처럼 보인다).
- 시청자 역할 에이전트도 실수한다(오늘 깨진 글자 1개, 병렬 명령 1번) — 회차 receipt에 caveat로 남긴다.
