# AIRI 지식 대량 적재 생성 계약 (2026-08-27)

> **왜 이 문서가 생겼나.** 2026-08-27 실측: replay 세 회차(기준선 run 04 포함) 전부에서 지식 계층이
> `enabled=True, ready=True, documents=0, chunks=0, retrievals=0` 이었다. **켜져 있고 준비됐는데 비어
> 있었다.** 사용자 코멘트가 지목한 "지식 결함" 턴들("매도 월드컵" 되물음, "암베사 팔다리 짤렸어??"에
> 폴백, 게임을 영화로 지어냄)은 모델 역량 한계가 아니라 **찾아볼 데가 없었던 것**이다. 파인튜닝으로는
> 닫히지 않는다. 상세 = `AIRI-RATING-PROVENANCE-AND-COMMENT-ANALYSIS-2026-08-27.md` §2.2.
>
> 이 문서는 **클라우드 LLM이 지식 레코드를 대량 생성할 때 지켜야 할 계약**이다. 생성물은
> `knowledge_ingest.py`(오프라인 전용, 네트워크·모델 미접촉)로 검증 후 적재한다.

## 1. 지연 안전성 — 먼저 확인할 것

대량 적재가 방송 지연을 해치지 않는다는 근거는 코드에 있다.

| 항목 | 값 | 출처 |
|---|---|---|
| 턴당 주입 상한 | **`max_chars=1600`**, `top_k=4` | `knowledge_store.retrieve()` 기본값 |
| 청크 크기 | 700자 (겹침 100자) | `CHUNK_CHARS` / `CHUNK_OVERLAP` |
| 주입 시점 | 검색이 히트한 턴에만 | `knowledge_runtime.retrieve()` 호출부 |

**10만 건을 넣어도 한 턴에 들어가는 것은 최대 1,600자다.** num_ctx 4096 기준 약 40%이고, 히트한 턴에만
붙는다. 적재량은 지연이 아니라 **디스크와 검색 품질**의 문제다.

## 2. 레코드 스키마

```json
{
  "approved": true,
  "title": "암베사 메다르다",
  "aliases": ["암베사", "Ambessa", "암베사메다르다", "메다르다"],
  "answer_summary": "리그 오브 레전드·아케인에 나오는 녹서스의 장군. ...",
  "content": "방송 중 시청자 질문에 바로 쓸 수 있는 서술. 700~3000자 권장.",
  "source": "출처 표기",
  "provenance": "cloud-llm-curated-2026-08-27",
  "version": "2026-08-27",
  "reviewed_at": "2026-08-27T00:00:00Z",
  "expires_at": null
}
```

| 필드 | 필수 | 상한 | 비고 |
|---|---|---|---|
| `approved` | **필수** | `true` 고정 | `true` 가 아니면 레코드 전체 거부 |
| `content` | **필수** | 24,000자 | 실제 권장은 **700~3,000자** (§4) |
| `title` | 필수 | 300자 | **검색 가중치 4.0 — 가장 중요** |
| `aliases` | 사실상 필수 | 16개, 각 80자 | 없으면 회수 실패 (§4) |
| `answer_summary` | 권장 | 400자 | 방송에서 바로 읽을 수 있는 한 문단 |
| `source` | 필수 | 300자 | |
| `provenance` | 권장 | 300자 | 기본값 `local-approved` |
| `version` | 권장 | 300자 | 기본값 `unknown` |
| `published_at` / `reviewed_at` / `expires_at` | 선택 | ISO8601 | `expires_at` 지난 문서는 **검색에서 자동 제외** |
| `content_sha256` | 선택 | 64 hex | 주면 본문과 대조 검증 |

## 3. 거부되는 것 (전량 실패하므로 반드시 지킬 것)

모든 텍스트 필드가 아래 검사를 통과해야 한다. 하나라도 걸리면 **그 레코드는 통째로 거부**된다.

- **주입 패턴 금지** — `ignore previous` / `ignore all previous` / `system prompt` / `developer message`
  / `<|act` `<|call` `<|delay` / `jailbreak` (대소문자 무관). ⚠️ **프롬프트 엔지니어링·AI 보안을 주제로
  하는 레코드는 본문에 이 표현이 자연스럽게 들어가 거부된다.** 그런 주제는 표현을 바꿔 쓰거나 제외한다.
- 제어문자(`\x00-\x08` 등), 양방향 텍스트 제어문자(BIDI)
- 빈 문자열, 상한 초과
- `approved` 누락

## 4. 회수율을 결정하는 두 가지 (여기서 성패가 갈린다)

검색은 **BM25 전문검색**이고 가중치가 `title 4.0 / aliases 2.0 / answer_summary 1.0 / content 0.5` 다.
그리고 **질의어는 2자 미만이면 버려진다.**

### 4-1. 한 레코드 한 주제, 700~3,000자

`content` 24,000자를 넣으면 **40개 청크로 쪼개져 서로 경쟁**하고, top_k=4·1,600자 예산에서 정작 필요한
조각이 밀린다. 주제를 쪼개서 레코드를 늘리는 쪽이 항상 낫다.

- ❌ "리그 오브 레전드 챔피언 전체" 1건 24,000자
- ✅ "암베사 메다르다" / "벡스" / "아케인 시즌2 줄거리" … 각 1,000자

### 4-2. aliases 에 시청자가 실제로 치는 표기를 전부 넣는다

시청자는 정식 명칭을 안 쓴다. 다음을 모두 넣는다(최대 16개).

- 줄임말·별명 — `암베사`, `메다르다`
- 영문/한글 병기 — `Ambessa`
- 띄어쓰기 변형 — `암베사메다르다`
- 흔한 오타·표기 흔들림 — `암배사`
- 커뮤니티 표기 — 방송에서 실제로 쓰는 말

한국어 조사(`암베사가`, `암베사는`)는 store 가 일부 정규화하므로 alias 에 넣지 않아도 된다.
**단 1자 단어는 질의에서 버려지므로 1자 alias 는 무의미하다.**

## 4-3. 무엇을 만들지는 실제 채팅이 정한다

주제를 짐작해서 만들지 않는다. 무관한 문서가 많을수록 BM25 회수 품질도 같이 떨어진다.
보유 리플레이의 시청자 발화에서 후보 어휘를 뽑아 그 목록으로 범위를 잡는다.

```powershell
python ollama-proxy\knowledge_batch.py terms --review <저장소 밖>\*\review.jsonl `
    --min-count 2 --output <저장소 밖>\kb-candidate-terms.txt
```

2026-08-27 실측: review 14개·1,386턴이 실은 **서로 다른 메시지 221건**이었다(같은 고정 채팅을
14회 리플레이한 것이라 중복을 지우지 않으면 빈도가 14배로 부풀려진다 — 도구가 메시지 단위로
중복을 지운다). 거기서 나온 실질 후보는 **20~30종**이었다: 그레·둥그레·둥하, 풀트·풀트로, 영도,
암베사, 촉슈·촉각슈트, 링피트, 장갑, 댄스 등.

즉 **이 회차의 지식 결함은 수십 건이면 대부분 닫힌다.** 대형 덤프를 통째로 적재할 이유가 없다.
다만 이 목록은 *이 채팅 세트* 기준이므로, 새 방송·새 주제마다 추출을 다시 돌리는 **방송 준비
루틴**으로 상시화해야 한다.

후보 목록은 **큐레이션 전제**다. 성희롱성 채팅에서 온 어휘처럼 지식 문서가 될 수 없는 말이
섞여 나오므로, 레코드로 만들 대상은 생성 단계에서 걸러야 한다.

## 5. 수집 범위 (2026-08-27 사용자 결정 — 4개 전부)

| 우선순위 | 범위 | 지침 |
|---|---|---|
| 1 | **게임·콘텐츠** | 다루는 게임의 캐릭터·아이템·패치·신작. 시청자 질문이 가장 많이 나오는 영역. **패치·시즌 의존 지식은 `expires_at` 필수.** |
| 2 | **밈·슬랭·방송문화** | `둥하`·`매도 월드컵`·`ㄱㄴㅇ` 같은 스트리밍 밈과 줄임말. **Wikimedia 파이프라인으로는 절대 안 들어오는 영역이고, 실측 실패가 여기 몰려 있다.** 뜻뿐 아니라 **어떤 맥락에서 쓰이는지**를 쓴다. |
| 3 | **AIRI 자기 설정** | 캐릭터 헌법, `사장님` 호칭, 하드웨어 자학 개그 등. **지어냄 방지에 직접 효과**가 있다. `provenance` 를 내부 문서로 표기하고 외부 출처를 만들지 않는다. |
| 4 | **시사·일반상식** | 시효가 짧으므로 `expires_at` 을 짧게 잡는다. 범위가 넓고 효용이 낮아 마지막. |

## 6. 배치 규칙

`knowledge_ingest.py` 상한이 **파일당 ≤1,000 레코드 AND ≤2MB** 다. 대량 적재는 반드시 분할한다.

### ⚠️ 경로 함정 — 반드시 절대경로

`runtime_path()` 는 **상대경로를 CWD 기준으로 푼다.** runtime-dir 밖으로 나가면 ingest 가
`path must be inside the configured runtime directory` 로 거부하는데, 메시지가 `{"error":
"KnowledgeInputError"}` 하나뿐이라 원인이 안 보인다. 2026-08-27 실측에서 실제로 겪었다.

**배치 파일은 runtime 디렉터리 안에 두고, `--input` 에 절대경로를 준다.**

```powershell
# 0) 사전 검증 — ingest 가 그 경로를 받아줄지까지 함께 확인한다
python ollama-proxy\knowledge_batch.py lint --input <절대경로>\kb-game-001.jsonl `
    --runtime-dir ollama-proxy\runtime
# 1) 검증만 (ingest 기본이 dry-run)
python ollama-proxy\knowledge_ingest.py --input <절대경로>\kb-game-001.jsonl
# 2) 실제 적재
python ollama-proxy\knowledge_ingest.py --input <절대경로>\kb-game-001.jsonl --apply
```

- 파일명 규칙 `kb-<범위>-<번호>.jsonl` (예: `kb-game-001.jsonl`)
- 레코드 평균 2,000자 기준 **파일당 약 700~900건**이 2MB 상한에 맞는다
- `title` 중복은 배치 간에도 피한다 — `lint` 가 여러 파일을 한 번에 받아 배치 간 중복도 잡는다

## 7. 클라우드 LLM 에 그대로 줄 프롬프트

```
너는 한국어 AI 버튜버의 방송용 지식 베이스를 만든다. 아래 스키마의 JSONL 을 생성해라.
한 줄에 레코드 하나. 설명·머리말·코드펜스 없이 JSONL 만 출력한다.

{"approved": true, "title": "...", "aliases": ["..."], "answer_summary": "...",
 "content": "...", "source": "...", "provenance": "cloud-llm-curated-<날짜>",
 "version": "<날짜>", "reviewed_at": "<ISO8601>", "expires_at": null}

규칙:
1. 한 레코드는 한 주제만 다룬다. content 는 700~3000자. 절대 24000자를 넘기지 않는다.
2. title 은 정식 명칭. aliases 에는 시청자가 실제로 칠 표기를 최대 16개 넣는다 —
   줄임말, 별명, 영문 표기, 띄어쓰기 변형, 흔한 오타. 1자짜리 별칭은 넣지 않는다.
3. answer_summary 는 방송에서 그대로 읽어도 자연스러운 한 문단, 400자 이내.
4. content 는 시청자 질문에 답할 수 있는 사실 서술. 추측·창작 금지. 모르면 그 레코드를 만들지 않는다.
5. 다음 표현을 어떤 필드에도 넣지 마라 (자동 거부된다):
   "ignore previous", "system prompt", "developer message", "jailbreak", "<|act", "<|call", "<|delay"
6. 패치·시즌·시사처럼 시효가 있는 지식은 expires_at 을 반드시 지정한다.
7. 제어문자·양방향 제어문자를 넣지 않는다.

이번 배치 주제: <범위와 목록>
목표 건수: <N>
```

## 8. 적재 후 반드시 할 것 — 회수율 실측

적재는 성공했는데 검색이 안 걸리면 아무 의미가 없다. **실측 실패 질의로 확인한다.**

고정 질의 세트가 `ollama-proxy/eval/knowledge_probe_queries.txt` 에 있다. 전부 실측 실패 지점이다 —
`암베사`(run 04 turn 46 폴백), `매도 월드컵`(s3-r2 turn 19 되물음), `버니가든2`(turn 37 템플릿),
`머함`(turn 62 슬랭 미인지), `둥하`(turn 2~7 4연속 같은 패턴), `ㄱㄴㅇ`(turn 33 에코).

```powershell
python ollama-proxy\knowledge_batch.py probe `
    --queries ollama-proxy\eval\knowledge_probe_queries.txt --min-hit-rate 0.9
```

각 질의가 히트하고, 히트한 문서가 **의도한 문서**인지 확인한다. 히트했는데 엉뚱한 문서가 나오면
`title`·`aliases` 설계 문제다. `--min-hit-rate` 미달이면 exit 1 이므로 게이트로 쓸 수 있다.

파이프라인 자체는 2026-08-27 에 end-to-end 로 확인했다 — 2건 배치를 lint → ingest(`inserted: 2`)
→ probe 했고, 질의 `암베사` 가 **alias 를 통해** 문서 `암베사 메다르다` 를 회수했다. 나머지 5개 질의는
해당 지식이 아직 없어 정상적으로 미스로 잡혔다(회수율 1/6).

## 8-2. 소스 — 나무위키 덤프 (2026-08-27 사용자 결정)

사용자 결정: **나무위키 덤프를 소스로 쓰되, 라이선스상 비공개 테스트로 한정한다.** 그리고 시효
문제 때문에 **2층으로 나눈다.**

| 층 | 소스 | 대상 |
|---|---|---|
| 1 | 나무위키 덤프 | 잘 안 변하는 것 — 밈·슬랭·방송문화, 게임 기본 설정 |
| 2 | 클라우드 LLM (덤프 밖) | 2022 이후 — 최근 캐릭터·패치·신작·최신 유행어 |

**가용 덤프(2026-08-27 조사)**: [heegyu/namuwiki](https://huggingface.co/datasets/heegyu/namuwiki)
2022-03-01 / 867,024 문서 / 3GB, [heegyu/namuwiki-extracted](https://huggingface.co/datasets/heegyu/namuwiki-extracted)
본문 추출본, [Bingsu/namuwiki_20210301_filtered](https://huggingface.co/datasets/Bingsu/namuwiki_20210301_filtered)
2021-03-01, [Internet Archive](https://archive.org/details/namuwikidumps) 2015~2017.
**2024~2025 덤프는 확인되지 않았다.** 나무위키가 크롤링 부담을 줄이려고 공식 덤프를 제공하므로
직접 크롤링하지 않는다.

**시효 한계를 명확히 한다.** 사용자 예시인 `암베사`는 아케인 시즌2(2024-11) 맥락으로 화제가 된
인물이라 **2022 덤프로는 못 메운다.** 실측 실패 질의 중 `암베사`·`버니가든2` 는 2층 대상이고,
`둥하`·`ㄱㄴㅇ`·`머함` 은 1층으로 커버된다.

**원문을 그대로 넣지 않는다.** 나무위키 문서는 흔히 5만~20만 자라 한 문서가 70~280 청크로
쪼개져 `top_k=4` 를 통째로 잡아먹고, 각주·틀·드립·과격 표현이 그대로 들어온다. 실측에서 AIRI 는
받은 것을 되읽는 실패가 25건(12.6%)이었으므로 원문 투입은 그 위험을 키운다.
**덤프는 참고 자료로 주고, §7 프롬프트로 700~3,000자 레코드를 생성한다.**

**소스 정책 등록.** 레포는 `create_wikimedia_source_policy.py` 처럼 소스마다 `license` ·
`license_url` · `attribution` · `attribution_url` 을 기록하고 사람이 `approve-source` ·
`approve-license` · policy_id 를 확인하는 게이트를 둔다. 나무위키 정책에도
`CC BY-NC-SA 2.0 KR` 과 **"비공개 테스트 한정 — 방송 송출·수익화 전 재검토"** 를 명시해,
공개 단계에서 자동으로 걸리게 한다.

## 9. 이 트랙이 로드맵에 갖는 의미

지식 계층이 비어 있는 상태에서 측정된 것: 기준선 1.7576, 06b-r3 1.9024, s2-r2 2.2290, s3-r2 3.0976,
그리고 M7 의 S0~S4 전체. **행동만 조율하고 재료는 비어 있었다.** 로드맵 v3 가 이미 "모델을 굶기는
구조"를 병목으로 지목했는데, 지식 계층은 그보다 더 문자 그대로 굶고 있었다.

적재 후 같은 07 입력으로 재실행하면 **지식 효과만 분리된 한 변수 실험**이 된다(계약 §5 "한 run 에
한 변수"에 부합). 적재 전후 비교는 사용자 결정 사항이다.
