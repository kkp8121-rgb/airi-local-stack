# AIRI 타계책 — "코드 제어 vs 파인튜닝" 이분법을 벗어나는 계획 (2026-08-26)

> 사용자 goal("두 축을 갈팡질팡하며 단계를 돌파하지 못한다 — 타계책을 찾아라")에 대한 답이다. 렌즈 4개
> (모델 축·추론 시점 설계·재료 공급·의사결정 규율)의 독립 조사와 각 상위 제안에 대한 회의적 반박 검증
> (에이전트 12, 전부 read-only)을 거쳐, 감독이 수치·코드를 직접 재대조한 것만 남겼다. 모든 제안의 문자 그대로의
> 형태는 반박에서 기각됐고, 살아남은 것은 반박이 붙인 **조건**들이다. 이 문서는 그 조건들을 순서로 묶은 것이다.

## 0. 결론

이분법이 틀렸다. 지금 막고 있는 것은 "규칙을 더 넣을까, 학습을 시킬까"가 아니라 다음 셋이다.

1. **런타임이 모델에게 자기 열화 출력을 되먹인다.** 같은 모델·같은 99턴·같은 샘플링(0.45/0.9/1.05)에서 run 04→05는
   "음" 오프너 1→48, "?" 종결 20→78, 브리핑 재료 사용 35→0으로 갔다. 바뀐 것은 history에 남는 내용(후원 의례→자기
   되묻기)뿐이다. 운영 경로에도 같은 고리가 있다: `foreground_context.py:80-82` `_short_direct_answer`는 현재 메시지가
   5어절 이하이고 직전 AIRI 응답에 '?'가 있으면 그 응답을 반드시 유지하고(실제 채팅은 p50 9자, run 05 AIRI 응답 78%가
   의문문 → 매 턴 유지), `airi_memory.py:2208`은 journal 회수에 assistant 행을 포함한다. 하드코딩 의례("고마워." 붕괴)든
   모델 자신의 되묻기("음... 뭐가 X인데?")든 **되먹인 문형이 곧 다음 붕괴 모드**다.
2. **메모형 재료는 이 모델이 수용하지 않는다.** run 05에서 브리핑이 관련 토큰을 실어 준 12턴 중 사용 0/12, `방금 흐름`
   다른 시청자 줄 사용 2/99. P1(재료 공급) 축을 "브리핑 줄 추가"로 더 미는 것은 08-19~20에 사실 활용 7%에서 동결된
   것과 같은 벽이다. 병목은 공급이 아니라 수용이다.
3. **1회 측정 위에 결정을 쌓았다.** 픽업은 결정론(같은 99 message_id 재현 확인)이지만 생성은 seed 고정이 없다. run 05
   한 표본으로 D/E/F를 골랐고, 6라운드 합성 매트릭스도 매번 n=1이었다. 노이즈 바닥을 잰 적이 없다.

따라서 타계책은 "세 번째 축"이 아니라 **순서와 규율**이다: 되먹임 고리를 proxy에서 끊고(운영 동작), 복제로 노이즈를 재고,
한 번에 한 변수만 바꿔 사람이 채점한다. 모델 체급과 파인튜닝은 그 뒤에만, 그리고 실제 채팅에서 나온 사람 검증 답변만을
데이터로 삼는 조건에서만 검토한다.

## 1. 돌파의 정의 (사전 등록)

같은 99턴 입력(`chzzk-12901656.jsonl` 앞 1,500건, 픽업 결정론)에서 사람 채점으로:

- **3축 합성**(방송다움·맥락 유지·반응 적절성 평균) **≥ 3.0** — run 04 사람 기준선 1.76, run 05 Claude 참고 1.72
- `critical_failure` 0, `silence_or_filler` ≤ 25%(기준선 45.5%), 말투 ≥ 3.5, 사실성 ≥ 기준선 2.75
- 후보당 복제 ≥ 2회 중 사람이 1회 채점, 자동 시그니처(음 오프너·'?' 종결·완전 에코·첫 2어절 고유율)는 채점자에게 표시만
  하고 판정에 쓰지 않는다(계약 §6).

5축 평균으로 판정하지 않는다 — run 05가 보여주듯 말투·사실성은 filler 악화를 가린다.

## 2. 순서 — 한 번에 한 변수, 각 단계에 예측·kill·예산

| 단계 | 변수 | 무엇을 | 사전 예측 | advance / kill | 예산 |
|---|---|---|---|---|---|
| **S0 측정 위생** | 없음 | run 05 구성 그대로 3회 복제(사람 채점 없음)로 시그니처 평균·SD 기록; `summarize_ratings.py --baseline`; 픽업 결정성 pytest; run 05 사람 채점으로 A+B 대조군 확정 | — | 복제 중 붕괴하지 않는 표본이 있으면 D/E/F 결정 재검토 | 0.5일, GPU 학습 0 |

| **S4 픽업 스킵·배치 (디렉터)** | 픽업 정책 | 스트리머처럼 채팅의 대부분은 읽지 않고 고른다: 내용 토큰 임계(`min_content_tokens`, 기본 0=byte 동일), 같은 문장 ≥3 합창은 `batched_chat`으로 묶어 코드 소유 "다들 X 하네" 줄 | 정답 모드 ≥40/99, 완전 에코 ≤5, 원 방송 맥락 의존 감소 | 턴 페어 비교 불가 → 세션 단위 비교로 사전 등록 | eng ≤3h |
| **S5 모델 축 1회 진단 (채택 아님)** | 모델 | S1 적용 뒤에만. qwen3:8b Q4를 TTS 미기동·전량 GPU 적재(`/api/ps` size_vram==size 확인)·think off·run 05와 같은 샘플링·seed 2개로 재생; 결과는 "체급이 병목인가"의 천장 참조. 8B는 TTS와 공존 불가(LLM 예산 ≈4~5GB vs 필요 ≈6.1GB)라 운영 후보가 아니다. 파인튜닝: **2주간 금지.** 재진입 조건(전부): S1~S5 뒤에도 3축 합성 < 3.0, S5에서 큰 모델이 +0.6 이상(용량 병목 실측),
실제 채팅 입력 + 사람이 4점 이상으로 검증한 답변(채점 루프에서 축적되는 `ratings-human.json`의 ≥4 턴과 채점자 교정문)
≥ 300턴 확보. 즉 학습 데이터의 유일한 합법적 출처는 이 채점 루프 자체다 — 합성 템플릿이 아니라.

## 3. 하지 말 것 (반박에서 확정)

- 계약에 "되묻지 마"·"음으로 시작하지 마" 같은 규칙 문장을 더 얹지 않는다 — "매번 질문으로 끝내지 마"가 이미 있는데 78/99가
  질문으로 끝났다. 지시 천장은 로드맵 §0에서 3회 실증됐다.
- 문형별 땜질(예: "음"을 `DEGENERATE_ECHO_PREFIXES`에 추가)을 하지 않는다 — 그것이 곧 "하드코딩↔파인튜닝 진동"이며, B 수리 뒤
  새 문형으로 재발한 것이 증거다. 고리를 끊는 것과 문형 하나를 막는 것은 다르다.
- 메모형 브리핑 줄(용어집·대기 채팅 다이제스트)을 더 넣지 않는다 — 수용률 0/12·2/99.
- 실제 채팅 행을 memory journal에 미리 주입하지 않는다 — user/assistant 쌍 완결 턴만 회수되고, 가짜 assistant 반쪽을 넣으면
  붕괴를 사전 주입하는 셈이다.
- 한 run에 두 변수 이상 바꾸지 않는다({모델, 프롬프트, 결정론 계층, history/재료, 픽업} 중 정확히 하나). A+B처럼 묶으면
  귀속이 불가능하다(이번에 배운 값).
- 정규식 시그니처로 사람 채점을 대체하거나 kill 게이트로 쓰지 않는다(계약 §6). 시그니처는 표시 전용.
- qwen3:8b를 운영 모델로 승격하지 않는다(VRAM·지연). 파인튜닝을 2주 안에 다시 시작하지 않는다.

## 4. 왜 이것이 "돌파"인가

지금까지의 모든 라운드는 모델이 만든 결과를 보고 규칙을 더하거나 학습을 더했다. 그런데 run 04·05가 보여준 것은 결과의
대부분이 **런타임이 모델에게 무엇을 다시 보여주느냐**로 결정된다는 사실이다. 그 변수는 한 번도 통제된 적이 없다(history 8턴은
합성 매트릭스 계약값이었다). S1이 통제하는 순간, 이후 S2~S5의 측정이 처음으로 모델 자체를 재게 되고, 그때 비로소 "체급을
올릴지, 학습할지"가 증거로 결정된다. 순서를 지키면 2주·eng ≤24h 안에 답이 나온다.

## 5. 즉시 결정 요청

1. S0 실행 승인(측정 전용, 운영 변경 없음) — 스택 기동 1회, 복제 3회.
2. S1 승인 — proxy 운영 동작 변경(flag, 기본 byte 동일): journal 회수 assistant 제외 옵션 + foreground 유지 assistant 본문 비우기.
3. run 05 사람 채점(대조군) — S1 순증분을 분리하려면 먼저 필요하다.
